        <p>Add <strong>Flagger</strong> to your existing <strong>platform-config</strong> GitOps repo, wired to your stack (NGINX Ingress + kube-prometheus-stack).</p>
<p>Using Flux’s <strong>OCI Helm repo</strong> for Flagger (recommended) and letting the Helm chart create its own CRD. I’ll also point Flagger at your Prometheus (<code>kube-prometheus-stack-prometheus.monitoring:9090</code>).</p>
<hr>
<h1>1) Add Flagger’s Helm source (OCI)</h1>
<p><strong>File:</strong> <code>clusters/microk8s-prod/infra/core/helmrepo-flagger.yaml</code></p>
<pre><code class="language-yaml">apiVersion: source.toolkit.fluxcd.io/v1
kind: HelmRepository
metadata:
  name: flagger-charts
  namespace: flux-system
spec:
  interval: 1m
  type: oci
  url: oci://ghcr.io/fluxcd/charts
</code></pre>
<blockquote>
<p>Using the OCI chart is the Flux/Flagger-docs path for GitOps installs. (<a href="https://docs.flagger.app/install/flagger-install-with-flux?utm_source=chatgpt.com" title="Flagger Install with Flux">docs.flagger.app</a>)</p>
</blockquote>
<p>Make sure your existing <code>clusters/microk8s-prod/infra/core/kustomization.yaml</code> includes this new file in <code>resources:</code>.</p>
<hr>
<h1>2) Create a Flagger app folder under <code>gitops/apps</code></h1>
<pre><code>gitops/apps/flagger/
  kustomization.yaml
  namespace.yaml
  release.yaml
</code></pre>
<p><strong><code>gitops/apps/flagger/namespace.yaml</code></strong></p>
<pre><code class="language-yaml">apiVersion: v1
kind: Namespace
metadata:
  name: flagger-system
</code></pre>
<p><strong><code>gitops/apps/flagger/release.yaml</code></strong> (HelmRelease)</p>
<pre><code class="language-yaml">apiVersion: helm.toolkit.fluxcd.io/v2
kind: HelmRelease
metadata:
  name: flagger
  namespace: flagger-system
spec:
  interval: 5m
  targetNamespace: flagger-system
  install:
    createNamespace: true
    crds: Create         # let Helm install Flagger&#39;s CRD
  upgrade:
    crds: Create
  chart:
    spec:
      chart: flagger
      version: &quot;&gt;=1.32.0&quot;   # or pin a specific version
      sourceRef:
        kind: HelmRepository
        name: flagger-charts
        namespace: flux-system
  values:
    meshProvider: nginx
    metricsServer: &quot;http://kube-prometheus-stack-prometheus.monitoring:9090&quot;
    logLevel: info
</code></pre>
<ul>
<li>Flagger’s chart exposes <code>meshProvider</code> and <code>metricsServer</code>; setting <code>crds</code> for install/upgrade is supported by Flux Helm controller. (<a href="https://fluxcd.io/flux/components/helm/api/v2/?utm_source=chatgpt.com" title="Helm API reference v2">fluxcd.io</a>)</li>
<li>You can install Flagger <strong>in any namespace</strong> so long as it can reach Prometheus on 9090. (<a href="https://docs.flagger.app/install/flagger-install-on-kubernetes?utm_source=chatgpt.com" title="Flagger Install on Kubernetes">docs.flagger.app</a>)</li>
</ul>
<p><strong><code>gitops/apps/flagger/kustomization.yaml</code></strong></p>
<pre><code class="language-yaml">apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - namespace.yaml
  - release.yaml
</code></pre>
<p>Now add <code>./flagger</code> to your existing <code>gitops/apps/kustomization.yaml</code> so it’s picked up with the rest of your apps.</p>
<hr>
<h1>3) Include in cluster Kustomizations</h1>
<p>If your <code>clusters/microk8s-prod/kustomizations/apps.yaml</code> already points at <code>./gitops/apps</code>, no change needed.
Otherwise, add a dedicated Kustomization:</p>
<p><strong><code>clusters/microk8s-prod/kustomizations/flagger.yaml</code></strong></p>
<pre><code class="language-yaml">apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization
metadata:
  name: flagger
  namespace: flux-system
spec:
  interval: 1m
  sourceRef:
    kind: GitRepository
    name: flux-system
  path: ./gitops/apps/flagger
  prune: true
  wait: true
  timeout: 5m
  dependsOn:
    - name: infra-core    # ensures helm repos &amp; ingress exist
    - name: infra-crds    # if you keep CRDs separate, keep this
</code></pre>
<p>And reference <code>flagger.yaml</code> from your aggregator <code>clusters/microk8s-prod/kustomizations/kustomization.yaml</code> (or add it to <code>apps.yaml</code> if that’s your pattern).</p>
<hr>
<h1>4) Ensure NGINX &amp; Prometheus are ready</h1>
<ul>
<li><p><strong>Prometheus URL</strong> used above is the kube-prometheus-stack default service name in <code>monitoring</code>. If yours differs, swap accordingly. Flagger queries Prometheus for built-in success-rate/latency checks. (<a href="https://docs.flagger.app/tutorials/nginx-progressive-delivery?utm_source=chatgpt.com" title="NGINX Canary Deployments">docs.flagger.app</a>)</p>
</li>
<li><p><strong>NGINX ingress metrics</strong> should be enabled &amp; scraped by Prometheus (controller metrics on, ServiceMonitor or scrape annotations). If you need it, enable:</p>
<ul>
<li><code>controller.metrics.enabled=true</code> and either <code>controller.metrics.serviceMonitor.enabled=true</code> (if you use Prom Operator) or <code>prometheus.io/scrape</code> annotations. (<a href="https://www.digitalocean.com/community/tutorials/how-to-progressively-deliver-releases-using-flagger-on-digitalocean-kubernetes?utm_source=chatgpt.com" title="How To Progressively Deliver Releases Using Flagger on ...">DigitalOcean</a>)</li>
</ul>
</li>
</ul>
<hr>
<h1>5) Commit &amp; push</h1>
<pre><code class="language-bash">git add \
  clusters/microk8s-prod/infra/core/helmrepo-flagger.yaml \
  gitops/apps/flagger

git commit -m &quot;feat(flagger): add Flagger (OCI chart), NGINX provider, Prometheus wiring&quot;
git push
</code></pre>
<hr>
<h1>6) Verify in-cluster</h1>
<pre><code class="language-bash"># Verify Flagger connectivity to Prometheus (HTTP test - more reliable)
kubectl -n flagger-system exec deploy/flagger-system-flagger -- wget -qO- http://kube-prom-prometheus.monitoring:9090/api/v1/query?query=up

# Check Flagger logs for successful connection
kubectl -n flagger-system logs deploy/flagger-system-flagger | grep &quot;Connected to metrics server&quot;
</code></pre>
<p>If the HelmRelease fails to reconcile, check the HelmRelease events and logs from <code>helm-controller</code> in <code>flux-system</code>.</p>
<hr>
<h1>7) (Optional) Flagger loadtester</h1>
<p>You can deploy the loadtester anywhere (often in the <strong>same namespace as the app</strong>, e.g., <code>ai</code>). We already included a loadtester manifest in the AI repo templates; if you want a “global” one managed by platform-config:</p>
<p><strong><code>gitops/apps/flagger/loadtester.yaml</code></strong></p>
<pre><code class="language-yaml">apiVersion: apps/v1
kind: Deployment
metadata:
  name: flagger-loadtester
  namespace: flagger-system
spec:
  replicas: 1
  selector:
    matchLabels: { app: flagger-loadtester }
  template:
    metadata:
      labels: { app: flagger-loadtester }
    spec:
      containers:
        - name: loadtester
          image: ghcr.io/fluxcd/flagger-loadtester:0.26.1
          ports:
            - name: http
              containerPort: 8080
---
apiVersion: v1
kind: Service
metadata:
  name: flagger-loadtester
  namespace: flagger-system
spec:
  selector:
    app: flagger-loadtester
  ports:
    - name: http
      port: 80
      targetPort: 8080
</code></pre>
<hr>
<h2>That’s it</h2>
<p>Once this reconciles, your <strong>ai-system</strong> repo can safely apply the <code>Canary</code> CR for the <code>gateway</code> (as in the template we built) and Flagger will drive progressive delivery using NGINX + Prometheus. For deeper reference and query examples, Flagger’s docs are solid and current. (<a href="https://docs.flagger.app/tutorials/nginx-progressive-delivery?utm_source=chatgpt.com" title="NGINX Canary Deployments">docs.flagger.app</a>)</p>
<p>If you want, I can tweak the HelmRelease to pin an exact Flagger chart version or add ServiceMonitor/PrometheusRule for Flagger’s own metrics.</p>
