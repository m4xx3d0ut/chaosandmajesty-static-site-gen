  1. # HTMX Blog Rendering Project Plan
  2. ​
  3. ## Objectives
  4. - Deliver an interactive blog experience using HTMX while preserving the fully static build pipeline.
  5. - Keep the existing YAML-driven content model and Node-based generator as the source of truth.
  6. - Maintain progressive enhancement: all content should remain reachable through standard links without HTMX.
  7. ​
  8. ## Current State
  9. - `smoke-test.yaml` defines a single `blog` page stub that today renders static markdown into `site-output/blog.html`.
  10. - Templates in `static-sitegen/templates/` do not currently emit HTMX attributes or partial fragments.
  11. - FEAT.md outlines best practices for an HTMX-first architecture that we can adapt to a static-generation workflow (fetching pre-rendered HTML instead of server-side fragments).
  12. ​
  13. ## Step-by-Step Plan
  14. 1. **Scope & Content Audit**
  15. - Review the existing blog page configuration inside `smoke-test.yaml` and any related markdown assets.
  16. - Confirm requirements for metadata (author, publish date, tags) and desired UX (inline article view, modal, dedicated page).
  17. - Capture open questions (pagination, tagging, comments) before implementation.
  18. ​
  19. 2. **Define Blog Content Model**
  20. - Decide on source-of-truth files (`content/blog/<slug>.md` plus front-matter or YAML entries).
  21. - Extend the configuration schema (`static-sitegen/lib/config.js` if needed) to load blog metadata and associate markdown bodies.
  22. - Document the model in FEAT.md or expand the configuration reference under `docs/configuration.md`.
  23. ​
  24. 3. **Template & Generator Enhancements**
  25. - Introduce dedicated EJS templates: `templates/blog/index.ejs`, `templates/blog/post.ejs`, and `templates/blog/partials/post-body.ejs`.
  26. - Update `generateSite.js` to:
  27. * Build a blog index page with post listings.
  28. * Emit standalone static post pages (`blog/<slug>.html`) for non-JS fallback.
  29. * Emit HTMX-friendly fragments (e.g., `blog/fragments/<slug>.html`) that contain only the article body.
  30. - Ensure sitemap generation links to the canonical post pages.
  31. ​
  32. 4. **Embed HTMX Library & Wiring**
  33. - Add the HTMX script to the shared head partial (`templates/partials/cm-head.ejs`) with integrity hashing and local fallback.
  34. - Confirm the script load respects existing console-themed layout.
  35. ​
  36. 5. **Interactive Blog Index UX**
  37. - Update the blog index template to:
  38. * Render the first article body server-side for immediate content.
  39. * Use `hx-get` to fetch fragment URLs, targeting a content container (`#blog-article`).
  40. * Apply `hx-push-url="true"` so URL updates reflect the selected post.
  41. - Provide loading indicator handling (`hx-indicator`) matching site styling.
  42. ​
  43. 6. **Progressive Enhancement & Fallbacks**
  44. - Ensure each post title remains a normal `<a href="blog/<slug>.html">` link so navigation works without HTMX.
  45. - Add a `noscript` notice if desired, but keep the experience functional when HTMX is absent.
  46. ​
  47. 7. **Build & Local Testing Pipeline**
  48. - Extend `build-site.sh` smoke checks to verify new fragment files exist.
  49. - Create targeted QA instructions (e.g., `make serve-local` then navigate between posts; confirm history/back button behavior).
  50. - Plan exploratory testing for mobile and console-themed layout regressions.
  51. ​
  52. 8. **Documentation & Examples**
  53. - Update README quick-start with new directories (`content/blog/`, `blog/fragments/`).
  54. - Expand FEAT.md (or a new doc) with HTMX fragment usage patterns specific to our static build.
  55. - Provide a sample blog post illustrating front-matter and markdown conventions.
  56. ​
  57. 9. **Future Enhancements (Optional Roadmap)**
  58. - Add pagination and tag filtering with `hx-select`/`hx-vals` support.
  59. - Consider lightweight search (pre-built JSON + HTMX requests) or comment integrations.
  60. - Evaluate hydration-free analytics or telemetry for blog interactions.
  61. ​
  62. ## Open Questions
  63. - Do we need author bios or listing pages at launch?
  64. - Are we targeting deployment on a CDN that supports custom headers required by HTMX history cache (e.g., caching fragment responses)?
  65. - Should we introduce tests under a new `tests/` directory or rely on manual QA for the first iteration?
