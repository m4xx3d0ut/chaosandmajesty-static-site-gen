  1. # RadioStatic Ansible Deployment
  2. ​
  3. This playbook deploys the production container image to the Linode VPS via SSH.
  4. ​
  5. ## Layout
  6. - `inventory/hosts.ini` – target hosts; override `ansible_host` before use.
  7. - `group_vars/all.yml` – defaults (install path, image coordinates, mounts).
  8. - `deploy.yml` – entrypoint playbook that applies the `app_deploy` and optional `stagit_mirror` roles.
  9. - `requirements.yml` – Ansible collections required (`community.docker`).
  10. - `roles/app_deploy` – renders Docker Compose configuration and deploys the site container.
  11. - `roles/stagit_mirror` – provisions a read-only stagit mirror for selected repositories.
  12. - `../config/stagit/` – manifest + shared assets consumed by the stagit workflows.
  13. ​
  14. ## Usage
  15. 1. Install dependencies:
  16. ```bash
  17. ansible-galaxy collection install -r requirements.yml
  18. ```
  19. 2. Provide the target host address by editing `inventory/hosts.ini` (defaults to
  20. `radiostatic.example`) or by passing
  21. `-i "prod," -e ansible_host=vps.example.com`.
  22. 3. Supply the registry coordinates and credentials (if private):
  23. ```bash
  24. ansible-playbook -i inventory/hosts.ini deploy.yml \
  25. -e image_registry=ghcr.io \
  26. -e image_namespace=radiostatic \
  27. -e image_name=radiostatic-site \
  28. -e image_tag=prod
  29. ```
  30. 4. When running from CI, export `REGISTRY_USERNAME`/`REGISTRY_PASSWORD` secrets
  31. and pass them via `-e registry_username=...` or environment variable lookup
  32. in the workflow.
  33. ​
  34. Key defaults (override in `group_vars/all.yml` or via extra-vars):
  35. - `webdav_host_path=/var/www/html/dav` keeps the host Joplin share mounted.
  36. - `letsencrypt_host_path=/etc/letsencrypt` shares existing certificates read-only.
  37. - `acme_webroot_host_path=/var/www/letsencrypt` is used for HTTP-01 challenges.
  38. - `auth_file_host_path=/etc/nginx/auth` mounts your existing WebDAV htpasswd directory read-only so credentials continue to work.
  39. - `disable_host_nginx=true` stops and disables the system nginx service at deploy time.
  40. ​
  41. The role will render a Docker Compose project in `{{ app_dir }}` (default
  42. `/opt/radiostatic`), ensure the WebDAV directory exists on the host, pull the
  43. specified image, and recreate the container. A health check against
  44. `http://127.0.0.1:{{ healthcheck_port }}` guards against silent failures.
  45. ​
  46. ## Static git mirror
  47. ​
  48. Set `stagit_enabled=true` to provision a read-only mirror rendered by
  49. [`stagit`](https://codemadness.org/stagit.html). The `stagit_mirror` role supports
  50. two operating modes:
  51. ​
  52. - **`stagit_mode: pull` (default)** – the VPS mirrors repositories directly. The
  53. role installs `stagit`/`git`, manages the SSH deploy key, and executes
  54. `/usr/local/bin/update-stagit.sh` during the play.
  55. - **`stagit_mode: push`** – CI generates the HTML and uploads it to the VPS. The
  56. role still creates the directory structure but skips package/key management and
  57. does not run the updater script, leaving CI to `rsync` the rendered output.
  58. ​
  59. In both modes the role ensures the git mirror directory (`stagit_repo_dir`),
  60. HTML output (`stagit_html_dir`), shared assets (`stagit_assets_dir`), and helper
  61. script are present. Set `stagit_manage_user=false` if you prefer to reuse an
  62. existing account (for example the pre-provisioned `deploy` user). Point
  63. `stagit_user`/`stagit_group` to that identity and ensure it can write under
  64. `stagit_base_dir`.
  65. ​
  66. Set `stagit_manage_user=false` if you prefer to reuse an existing account (for
  67. example the pre-provisioned `deploy` user). In that case, point `stagit_user`
  68. and `stagit_group` to the desired identity and ensure it can read the SSH key
  69. and write under `stagit_base_dir`.
  70. ​
  71. Define the mirror set one of two ways:
  72. ​
  73. 1. Populate `config/stagit/manifest.txt` with pipe-delimited entries
  74. (`url|branch|name|owner|description|homepage`). This manifest is copied to the
  75. VPS and can be reused by CI when running in push mode.
  76. 2. Or, set `stagit_repositories` to a list of dictionaries, e.g.:
  77. ​
  78. ```yaml
  79. stagit_enabled: true
  80. stagit_repositories:
  81. - url: git@lab-gitea:org/project-a.git
  82. branch: main
  83. name: project-a # optional; defaults to repo name
  84. owner: radiostatic # optional; shown on repo page
  85. description: Project A static docs
  86. homepage: https://radiostatic.example/project-a
  87. ```
  88. ​
  89. Assets live in `{{ stagit_assets_dir }}` (default `/srv/git/html/_assets`). The
  90. repository ships baseline files under `config/stagit/assets` (currently
  91. `style.css`). Leave `stagit_manage_assets=true` to copy those into place, or set
  92. it to false if CI uploads custom assets alongside the rendered HTML. The updater
  93. script symlinks any files
  94. listed in `stagit_shared_assets` (`style.css`, `logo.png`, `favicon.png` by default)
  95. into each rendered repository.
  96. ​
  97. Provide the read-only deploy key via `stagit_ssh_private_key` (ideally from an
  98. Ansible vault or CI secret) and seed host verification by populating
  99. `stagit_known_hosts` with dictionaries such as:
  100. ​
  101. ```yaml
  102. stagit_known_hosts:
  103. - name: lab-gitea.internal
  104. key: "lab-gitea.internal ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAA..."
  105. ```
  106. ​
  107. The updater uses the manifest file to decide which repositories to keep; removing
  108. an entry will prune both the bare mirror and the rendered HTML on the next run.
