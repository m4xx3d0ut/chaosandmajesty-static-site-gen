  14. <h1>HTMX Blog Rendering Project Plan</h1>
  15. <h2>Objectives</h2>
  16. <ul>
  17. <li>Deliver an interactive blog experience using HTMX while preserving the fully static build pipeline.</li>
  18. <li>Keep the existing YAML-driven content model and Node-based generator as the source of truth.</li>
  19. <li>Maintain progressive enhancement: all content should remain reachable through standard links without HTMX.</li>
  20. </ul>
  21. <h2>Current State</h2>
  22. <ul>
  23. <li><code>smoke-test.yaml</code> defines a single <code>blog</code> page stub that today renders static markdown into <code>site-output/blog.html</code>.</li>
  24. <li>Templates in <code>static-sitegen/templates/</code> do not currently emit HTMX attributes or partial fragments.</li>
  25. <li>FEAT.md outlines best practices for an HTMX-first architecture that we can adapt to a static-generation workflow (fetching pre-rendered HTML instead of server-side fragments).</li>
  26. </ul>
  27. <h2>Step-by-Step Plan</h2>
  28. <ol>
  29. <li><p><strong>Scope &amp; Content Audit</strong></p>
  30. <ul>
  31. <li>Review the existing blog page configuration inside <code>smoke-test.yaml</code> and any related markdown assets.</li>
  32. <li>Confirm requirements for metadata (author, publish date, tags) and desired UX (inline article view, modal, dedicated page).</li>
  33. <li>Capture open questions (pagination, tagging, comments) before implementation.</li>
  34. </ul>
  35. </li>
  36. <li><p><strong>Define Blog Content Model</strong></p>
  37. <ul>
  38. <li>Decide on source-of-truth files (<code>content/blog/&lt;slug&gt;.md</code> plus front-matter or YAML entries).</li>
  39. <li>Extend the configuration schema (<code>static-sitegen/lib/config.js</code> if needed) to load blog metadata and associate markdown bodies.</li>
  40. </ul>
  41. </li>
  42. </ol>
  43. <ul>
  44. <li>Document the model in FEAT.md or expand the configuration reference under <code>docs/configuration.md</code>.</li>
  45. </ul>
  46. <ol start="3">
  47. <li><p><strong>Template &amp; Generator Enhancements</strong></p>
  48. <ul>
  49. <li>Introduce dedicated EJS templates: <code>templates/blog/index.ejs</code>, <code>templates/blog/post.ejs</code>, and <code>templates/blog/partials/post-body.ejs</code>.</li>
  50. <li>Update <code>generateSite.js</code> to:<ul>
  51. <li>Build a blog index page with post listings.</li>
  52. <li>Emit standalone static post pages (<code>blog/&lt;slug&gt;.html</code>) for non-JS fallback.</li>
  53. <li>Emit HTMX-friendly fragments (e.g., <code>blog/fragments/&lt;slug&gt;.html</code>) that contain only the article body.</li>
  54. </ul>
  55. </li>
  56. <li>Ensure sitemap generation links to the canonical post pages.</li>
  57. </ul>
  58. </li>
  59. <li><p><strong>Embed HTMX Library &amp; Wiring</strong></p>
  60. <ul>
  61. <li>Add the HTMX script to the shared head partial (<code>templates/partials/cm-head.ejs</code>) with integrity hashing and local fallback.</li>
  62. <li>Confirm the script load respects existing console-themed layout.</li>
  63. </ul>
  64. </li>
  65. <li><p><strong>Interactive Blog Index UX</strong></p>
  66. <ul>
  67. <li>Update the blog index template to:<ul>
  68. <li>Render the first article body server-side for immediate content.</li>
  69. <li>Use <code>hx-get</code> to fetch fragment URLs, targeting a content container (<code>#blog-article</code>).</li>
  70. <li>Apply <code>hx-push-url=&quot;true&quot;</code> so URL updates reflect the selected post.</li>
  71. </ul>
  72. </li>
  73. <li>Provide loading indicator handling (<code>hx-indicator</code>) matching site styling.</li>
  74. </ul>
  75. </li>
  76. <li><p><strong>Progressive Enhancement &amp; Fallbacks</strong></p>
  77. <ul>
  78. <li>Ensure each post title remains a normal <code>&lt;a href=&quot;blog/&lt;slug&gt;.html&quot;&gt;</code> link so navigation works without HTMX.</li>
  79. <li>Add a <code>noscript</code> notice if desired, but keep the experience functional when HTMX is absent.</li>
  80. </ul>
  81. </li>
  82. <li><p><strong>Build &amp; Local Testing Pipeline</strong></p>
  83. <ul>
  84. <li>Extend <code>build-site.sh</code> smoke checks to verify new fragment files exist.</li>
  85. <li>Create targeted QA instructions (e.g., <code>make serve-local</code> then navigate between posts; confirm history/back button behavior).</li>
  86. <li>Plan exploratory testing for mobile and console-themed layout regressions.</li>
  87. </ul>
  88. </li>
  89. <li><p><strong>Documentation &amp; Examples</strong></p>
  90. <ul>
  91. <li>Update README quick-start with new directories (<code>content/blog/</code>, <code>blog/fragments/</code>).</li>
  92. <li>Expand FEAT.md (or a new doc) with HTMX fragment usage patterns specific to our static build.</li>
  93. <li>Provide a sample blog post illustrating front-matter and markdown conventions.</li>
  94. </ul>
  95. </li>
  96. <li><p><strong>Future Enhancements (Optional Roadmap)</strong></p>
  97. <ul>
  98. <li>Add pagination and tag filtering with <code>hx-select</code>/<code>hx-vals</code> support.</li>
  99. <li>Consider lightweight search (pre-built JSON + HTMX requests) or comment integrations.</li>
  100. <li>Evaluate hydration-free analytics or telemetry for blog interactions.</li>
  101. </ul>
  102. </li>
  103. </ol>
  104. <h2>Open Questions</h2>
  105. <ul>
  106. <li>Do we need author bios or listing pages at launch?</li>
  107. <li>Are we targeting deployment on a CDN that supports custom headers required by HTMX history cache (e.g., caching fragment responses)?</li>
  108. <li>Should we introduce tests under a new <code>tests/</code> directory or rely on manual QA for the first iteration?</li>
  109. </ul>
