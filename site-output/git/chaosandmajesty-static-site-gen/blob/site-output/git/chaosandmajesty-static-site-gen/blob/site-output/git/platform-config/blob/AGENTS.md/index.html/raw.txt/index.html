  14. <h1>Repository Guidelines</h1>
  15. <h2>Project Structure &amp; Module Organization</h2>
  16. <ul>
  17. <li><code>gitops/</code> contains Kustomize bundles for apps, shared infra, clusters, and guardrails; adjust overlays here before exporting live state.</li>
  18. <li><code>helm/</code> maintains chart values (<code>helm-gitea/</code>) and runner packaging (<code>helm-actions/</code>); keep overrides in sync with <code>gitops/</code>.</li>
  19. <li><code>docker/</code> holds CI build contexts (e.g., <code>capacitor-next/</code>); align images with the Helm values that reference them.</li>
  20. <li><code>tools/</code> offers automation (<code>./tools/export-all.sh</code>, <code>./tools/export-helm.sh</code>) and <code>bootstrap/</code> stores sensitive keys—keep decrypted copies local and out of Git.</li>
  21. </ul>
  22. <h2>Build, Test, and Development Commands</h2>
  23. <ul>
  24. <li><code>./tools/export-all.sh</code> snapshots Kubernetes objects into the repo; run after cluster updates to refresh manifests.</li>
  25. <li><code>./tools/export-k8s.sh namespace/name</code> exports a targeted resource tree when iterating on a single workload.</li>
  26. <li><code>helm lint helm/helm-gitea</code> and <code>helm template helm/helm-gitea</code> validate chart edits before pushing.</li>
  27. <li><code>kustomize build gitops/apps</code> (or a subdirectory) verifies overlays render cleanly; pipe to <code>kubectl apply --dry-run=server -f -</code> for schema checks.</li>
  28. </ul>
  29. <h2>Coding Style &amp; Naming Conventions</h2>
  30. <ul>
  31. <li>Prefer YAML with two-space indentation and sorted keys; keep filenames kustomize-friendly (<code>kustomization.yaml</code>, <code>&lt;component&gt;.yaml</code>).</li>
  32. <li>Shell scripts stay <code>bash</code>-compatible and use lowercase-with-dashes names.</li>
  33. <li>Enforce SOPS encryption on secrets via <code>sops -e file.yaml</code>; commit only the encrypted result.</li>
  34. </ul>
  35. <h2>Testing Guidelines</h2>
  36. <ul>
  37. <li>Validate Kustomize bundles via <code>kustomize build</code> + <code>kubectl apply --dry-run=server</code> per environment (<code>gitops/clusters/&lt;cluster&gt;</code>).</li>
  38. <li>For Helm releases, run <code>helm diff upgrade --install</code> (via plugin) against the target namespace to catch drift before applying.</li>
  39. <li>Keep encryption intact by running <code>sops -d file.yaml &gt;/dev/null</code> as a quick decryption check when reviewing secrets.</li>
  40. </ul>
  41. <h2>Commit &amp; Pull Request Guidelines</h2>
  42. <ul>
  43. <li>Follow the conventional-ish prefixes seen in history (<code>feat(component):</code>, <code>fix:</code>, <code>wip:</code>) and keep subject lines under 80 characters.</li>
  44. <li>Group related manifest, chart, and script changes in a single commit; include before/after context or exported command output in the body when relevant.</li>
  45. <li>PRs should cite the driving issue, describe rollout steps (e.g., scripts run, helm commands), and attach validation evidence (lint output, dry-run snippets, screenshots for UIs).</li>
  46. </ul>
  47. <h2>Security &amp; Configuration Tips</h2>
  48. <ul>
  49. <li>Store age keys only in <code>bootstrap/</code>; never embed plaintext credentials in manifests.</li>
  50. <li>When adding new exports, ensure <code>tools/gitea-enc-secrets-sops.sh</code> covers them so nightlies do not fail due to unencrypted secrets.</li>
  51. <li>Keep ingress hostnames, ports, and PVC names consistent with <code>helm-gitea-test/</code> templates to avoid breaking SSH and TLS automation.</li>
  52. </ul>
