  15. <h2>title: LV &amp; VG Management
  16. slug: lv-vg-management
  17. author: m4xx3d0ut
  18. summary: Playbook for reclaiming disks, adding them to Ubuntu LVM volume groups, and stretching the root filesystem safely.
  19. tags:
  20. - m4xx3d
  21. - linux
  22. - lvm
  23. - storage
  24. - devops
  25. publishedAt: 2024-10-20
  26. updatedAt: 2024-10-20</h2>
  27. <h2>TLDR;</h2>
  28. <ul>
  29. <li>Inspect disks and existing LVM layout before touching partitions, then create a new physical volume on the cleared SSD.</li>
  30. <li>Extend the volume group and logical volume with <code>vgextend</code>/<code>lvextend</code>, choosing either 100% of free space or a fixed increment.</li>
  31. <li>Finish by resizing the filesystem with <code>resize2fs</code> and verifying the expanded root volume with <code>df -h</code>.</li>
  32. </ul>
  33. <h2>Working Notes... In Graphic Detail...</h2>
  34. <p>To format an SSD to ext4 and include it as part of the root volume (<code>ubuntu--vg-ubuntu--lv</code>) in Ubuntu Server from the command line, you can follow these steps:</p>
  35. <ol>
  36. <li><p><strong>Check Available Disks and Partitions:</strong></p>
  37. <p>First, list the available disks and logical volumes to identify the correct device for the SSD:</p>
  38. <pre><code>
  39. </code></pre>
  40. </li>
  41. </ol>
  42. <p>bash
  43. lsblk</p>
  44. <pre><code>
  45. This will show a tree of block devices, making it easier to locate your SSD and logical volume.
  46. ​
  47. 2. **Check Current LVM Configuration:**
  48. ​
  49. Since you want to extend `ubuntu--vg-ubuntu--lv`, check your LVM setup:
  50. </code></pre>
  51. <p>bash
  52. sudo vgdisplay
  53. sudo lvdisplay</p>
  54. <pre><code>
  55. This will show you the volume group and logical volumes. Ensure you note the correct paths for the volume group (`ubuntu-vg`) and logical volume (`ubuntu-lv`).
  56. ​
  57. 3. **Partition the SSD (if not already done):**
  58. ​
  59. If the SSD is unpartitioned, create a partition using `fdisk` or `parted`. Here&#39;s an example using `fdisk`:
  60. </code></pre>
  61. <p>bash
  62. sudo fdisk /dev/sdX # Replace X with the correct letter for your SSD</p>
  63. <pre><code>
  64. Inside `fdisk`, create a new partition:
  65. - Press `n` to create a new partition.
  66. - Choose defaults for partition number and sector start/end.
  67. - Press `w` to write changes.
  68. ​
  69. 4. **Create a Physical Volume (PV):**
  70. ​
  71. If the SSD is now partitioned, you&#39;ll need to turn it into an LVM physical volume:
  72. </code></pre>
  73. <p>bash
  74. sudo pvcreate /dev/sdX1 # Replace sdX1 with the partition path of the SSD</p>
  75. <pre><code>
  76. 5. **Extend the Volume Group (VG):**
  77. ​
  78. Add the new physical volume to the existing volume group:
  79. </code></pre>
  80. <p>bash
  81. sudo vgextend ubuntu-vg /dev/sdX1 # Replace ubuntu-vg and sdX1 with your VG and partition</p>
  82. <pre><code>
  83. 6. **Extend the Logical Volume (LV):**
  84. ​
  85. Now extend the logical volume to use the space from the SSD:
  86. </code></pre>
  87. <p>bash
  88. sudo lvextend -l +100%FREE /dev/ubuntu-vg/ubuntu-lv</p>
  89. <pre><code>
  90. 7. **Resize the Filesystem:**
  91. ​
  92. After extending the logical volume, resize the filesystem to occupy the new space:
  93. </code></pre>
  94. <p>bash
  95. sudo resize2fs /dev/ubuntu-vg/ubuntu-lv</p>
  96. <pre><code>
  97. 8. **Verify the Changes:**
  98. ​
  99. Finally, check that the logical volume has been extended:
  100. </code></pre>
  101. <p>bash
  102. df -h</p>
  103. <pre><code>
  104. ---
  105. ​
  106. To delete an old Cinder volume from the disk on an Ubuntu server, you can follow these steps to safely remove it before formatting the disk.
  107. ​
  108. #### Steps to Remove the Old Cinder Volume:
  109. ​
  110. 1. **Identify the Cinder Volume:**
  111. </code></pre>
  112. <p>bash
  113. lsblk
  114. sudo pvdisplay</p>
  115. <pre><code>
  116. 2. **Stop OpenStack Cinder (if running):**
  117. </code></pre>
  118. <p>bash
  119. sudo systemctl stop cinder-volume
  120. sudo systemctl stop cinder-api</p>
  121. <pre><code>
  122. 3. **Delete the Cinder Volume from OpenStack (if applicable):**
  123. </code></pre>
  124. <p>bash
  125. openstack volume list
  126. openstack volume delete <volume-id></p>
  127. <pre><code>
  128. 4. **Wipe the Partition Table:**
  129. </code></pre>
  130. <p>bash
  131. sudo wipefs -a /dev/sdX
  132. sudo dd if=/dev/zero of=/dev/sdX bs=512 count=1</p>
  133. <pre><code>
  134. 5. **Remove LVM (if applicable):**
  135. </code></pre>
  136. <p>bash
  137. sudo lvchange -an /dev/<vg-name>/<lv-name>
  138. sudo lvremove /dev/<vg-name>/<lv-name>
  139. sudo pvremove /dev/sdX</p>
  140. <pre><code>
  141. 6. **Partition and Format the Disk:**
  142. </code></pre>
  143. <p>bash
  144. sudo mkfs.ext4 /dev/sdX1</p>
  145. <pre><code>
  146. ---
  147. ​
  148. Now that the drive has been cleared, add it to the existing volume group (`ubuntu-vg`) and extend the logical volume (`ubuntu-lv`).
  149. ​
  150. #### Steps to Add the Cleared Drive to the Existing Volume Group and Extend the Logical Volume:
  151. ​
  152. 1. **Create a Physical Volume (PV):**
  153. </code></pre>
  154. <p>bash
  155. sudo pvcreate /dev/sdX</p>
  156. <pre><code>
  157. 2. **Extend the Volume Group (VG):**
  158. </code></pre>
  159. <p>bash
  160. sudo vgextend ubuntu-vg /dev/sdX</p>
  161. <pre><code>
  162. 3. **Check the Volume Group:**
  163. </code></pre>
  164. <p>bash
  165. sudo vgdisplay</p>
  166. <pre><code>
  167. 4. **Extend the Logical Volume (LV):**
  168. </code></pre>
  169. <p>bash
  170. sudo lvextend -l +100%FREE /dev/ubuntu-vg/ubuntu-lv</p>
  171. <h1>or</h1>
  172. <p> sudo lvextend -L +50G /dev/ubuntu-vg/ubuntu-lv</p>
  173. <pre><code>
  174. 5. **Resize the Filesystem:**
  175. </code></pre>
  176. <p>bash
  177. sudo resize2fs /dev/ubuntu-vg/ubuntu-lv</p>
  178. <pre><code>
  179. 6. **Verify the Changes:**
  180. </code></pre>
  181. <p>bash
  182. df -h</p>
  183. <pre><code>
  184. #### Summary
  185. - You created a physical volume with `pvcreate`.
  186. - Added the new drive to the volume group using `vgextend`.
  187. - Extended the logical volume with `lvextend`.
  188. - Resized the filesystem with `resize2fs`.
  189. </code></pre>
