  14. <h1>Chaos &amp; Majesty Sitegen Import Guide</h1>
  15. <p>Use this checklist whenever we promote fresh posts from <code>blog/</code> into the Chaos &amp; Majesty site generator tree at <code>../../sshfs-mnt/chaosandmajesty-static-site-gen</code>. You can run <code>scripts/sync_cm_blog.py &lt;posts-root&gt; &lt;cm-root&gt;</code> to automate steps 2–4; the manual commands below describe what the script performs.</p>
  16. <h2>1. Prep the Source Material</h2>
  17. <ul>
  18. <li>Regenerate publishable files so every markdown file contains the <code>## TLDR;</code> and <code>## Working Notes...</code> sections: <code>python3 scripts/apply_offsec_tldr.py &amp;&amp; python3 scripts/format_blog.py --force</code>.</li>
  19. <li>Keep the sanitized hero assets under <code>blog/assets/&lt;slug&gt;/</code>. Only posts that declare <code>heroImage</code> need assets.</li>
  20. <li>Confirm the front matter uses one of the configured author IDs (<code>m4xx3d0ut</code>, <code>reneerules</code>, …) from <code>docs/blog-model.md</code>.</li>
  21. </ul>
  22. <h2>2. Copy Markdown into the Sitegen Repo</h2>
  23. <p>From the root of this repo:</p>
  24. <pre><code class="language-bash">rsync -av blog/*.md ../../sshfs-mnt/chaosandmajesty-static-site-gen/content/blog/
  25. </code></pre>
  26. <p>The generator reads straight from <code>content/blog/</code>, so no additional conversion is required.</p>
  27. <h2>3. Move Supporting Assets</h2>
  28. <p>For each folder under <code>blog/assets/</code> copy the files into the site generator’s blog asset tree (create the destination if it does not exist):</p>
  29. <pre><code class="language-bash">for dir in blog/assets/*; do
  30. slug=&quot;$(basename &quot;$dir&quot;)&quot;
  31. rsync -av &quot;$dir&quot;/ \
  32. ../../sshfs-mnt/chaosandmajesty-static-site-gen/static-sitegen/assets/static/img/blog/$slug/
  33. done
  34. </code></pre>
  35. <p>If you also curate the design source (<code>cm-source/</code>) keep it in sync so <code>prepare-cm-files.sh</code> can be re-run later:</p>
  36. <pre><code class="language-bash">rsync -av blog/assets/ \
  37. ../../sshfs-mnt/chaosandmajesty-static-site-gen/cm-source/static/img/blog/
  38. </code></pre>
  39. <p>The build step copies everything from <code>static-sitegen/assets/</code> to <code>site-output/</code>, so a manual copy there is unnecessary.</p>
  40. <h2>4. Normalize <code>heroImage</code> Paths</h2>
  41. <p>Update each markdown file that references a hero image so the path matches the static asset location. Example replacement:</p>
  42. <pre><code class="language-yaml">heroImage: assets/rnd-methods-madness/freedom-glider-trash-panda.png
  43. # becomes
  44. heroImage: assets/static/img/blog/rnd-methods-madness/freedom-glider-trash-panda.png
  45. </code></pre>
  46. <p>Use <code>sed -i</code> for bulk edits or update manually before committing in the sitegen repo.</p>
  47. <h2>5. Build &amp; Verify</h2>
  48. <p>Inside <code>../../sshfs-mnt/chaosandmajesty-static-site-gen</code>:</p>
  49. <pre><code class="language-bash">npm install # first run only
  50. npm run build || make preview
  51. </code></pre>
  52. <p>Open the generated <code>site-output/blog/index.html</code> (or run the preview server) and spot-check:</p>
  53. <ul>
  54. <li>TLDR and Working Notes render as expected.</li>
  55. <li>Hero images resolve correctly.</li>
  56. <li>Navigation lists the new posts by <code>publishedAt</code> order.</li>
  57. </ul>
  58. <h2>6. Commit &amp; Ship</h2>
  59. <ul>
  60. <li>Stage markdown plus any new assets in the sitegen repo.</li>
  61. <li>Reference the originating feature or issue in the commit message.</li>
  62. <li>Push and run the deployment workflow (or open a PR) per CM release practice.</li>
  63. </ul>
  64. <p>Keep this guide alongside the repo so future imports stay consistent.</p>
