## What the chart expects vs. what you set

1. **Stability level**

* Chart has **one** knob:

  ```yaml
  alloy:
    stabilityLevel: "generally-available"  # default
  ```
* You don’t need `--stability.level=...` flags at all. If you add them, you can only have one anyway (your pod shows only `generally-available`).
* Keep your config to GA components (which you are) and drop the flags:

  ```yaml
  alloy:
    extraArgs: []         # or omit
    stabilityLevel: "generally-available"
  ```

2. **HTTP/UI settings**

* You passed `--server.http.listen-addr` and `--server.http.ui-path-prefix`. The chart already exposes these via:

  ```yaml
  alloy:
    enableHttpServerPort: true
    listenAddr: 0.0.0.0
    listenPort: 12345
    uiPathPrefix: /
  ```
* Prefer the values block instead of CLI flags so **config-reloader** & probes stay consistent.

3. **Storage path / positions**

* Default `storagePath` is `/tmp/alloy`. You mounted an EmptyDir at `/tmp/alloy`, which persists **only for the pod lifetime** (not across pod restarts).
* If you want log tail positions to persist across pod restarts (reduce old-line replays & 400s), back this with a **hostPath** (DaemonSet) or a PVC (StatefulSet). For a DaemonSet, something like:

  ```yaml
  controller:
    volumes:
      extra:
        - name: alloy-data
          hostPath: { path: /var/lib/alloy }   # per-node path
  alloy:
    mounts:
      extra:
        - { name: alloy-data, mountPath: /tmp/alloy }
    storagePath: /tmp/alloy
  ```

  (Don’t add `start_at = "end"`; it isn’t a valid arg for `loki.source.kubernetes`—that’s why you saw an error. The “old sample” 400s are due to Loki limits + replayed old lines, not a missing `start_at`.)

4. **Var log mounts**

* The chart supports simple booleans:

  ```yaml
  alloy:
    mounts:
      varlog: true          # mounts /var/log from host
      dockercontainers: false
  ```
* You’re on MicroK8s/containerd with logs under `/var/snap/microk8s/common/var/log`; your explicit hostPath is fine (keep it). The boolean `varlog: true` would mount the standard `/var/log`, which isn’t your path.

5. **Service & ServiceMonitor for Alloy itself**

* By default the chart creates a `Service`, but **does not** create a `ServiceMonitor`:

  ```yaml
  service:
    enabled: true
  serviceMonitor:
    enabled: false
  ```
* If you want Prometheus to scrape Alloy’s own metrics, turn it on:

  ```yaml
  serviceMonitor:
    enabled: true
  ```

  (Independent of your other Prometheus fixes.)

6. **Config reloader**

* The chart includes a reloader sidecar by default (`v0.81.0`). You don’t need to manage it; leaving defaults is good.

7. **NetworkPolicy**

* Disabled by default. If you enable it later, be sure to allow egress to Loki/Tempo/Mimir and the Kubernetes API, or log/trace shipping + discovery will break.
