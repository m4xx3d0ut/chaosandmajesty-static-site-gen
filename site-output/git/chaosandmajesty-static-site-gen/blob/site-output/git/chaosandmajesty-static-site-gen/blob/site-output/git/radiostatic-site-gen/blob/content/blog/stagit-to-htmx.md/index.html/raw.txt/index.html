  27. <hr>
  28. <p>When RadioStatic first came online, Stagit handled the heavy lifting for the repository console. The static HTML it generated meant we could mirror git history with zero server state, drop the files into the build, and walk away confident that a basic web host could keep serving them. That simplicity bought us time to focus on the stories, not the scaffolding.</p>
  29. <h3>What Stagit originally gave us</h3>
  30. <ul>
  31. <li><strong>Repository index pages</strong> that enumerated projects with last-updated timestamps, commit counts, and default branches so readers could orient without cloning anything.</li>
  32. <li><strong>Commit detail and diff views</strong> generated as flat files, including per-file anchors and the trimmed patch so you could skim what changed without loading an external viewer.</li>
  33. <li><strong>Tag and release snapshots</strong> that mirrored annotated tags into their own subdirectories, which doubled as lightweight release notes.</li>
  34. <li><strong>RSS/Atom feeds</strong> straight from the git history, letting readers subscribe to repository activity the same way they would track new blog posts.</li>
  35. </ul>
  36. <p>Those affordances aligned with our early goal: a fully offline-capable archive that stayed in sync whenever we rebuilt the site.</p>
  37. <h3>Why we started phasing Stagit out</h3>
  38. <p>By mid-2024 the cracks were obvious. The Stagit pages were frozen until the next full site regeneration, so hot fixes or walkthrough updates lagged behind live repos. The static diff styling also clashed with the rest of the console, and tailoring it meant forking Stagit’s C templates. Worse, search and filtering remained a separate JavaScript widget bolted on after the pages loaded, which felt like duct tape. On 2025-03-18 we marked the Stagit console as “legacy” in the roadmap and froze feature work.</p>
  39. <h3>Enter the HTMX console</h3>
  40. <p>The replacement landed in two drops: a private alpha on 2025-06-02 and the public switch on 2025-07-09. Instead of pre-rendering every commit, we expose curated JSON endpoints during the build and let HTMX hydrate the console with targeted requests. The new stack layers:</p>
  41. <ul>
  42. <li><strong>HTMX partial swaps</strong> for the repo list, commit timelines, and file previews, keeping navigation snappy without full page reloads.</li>
  43. <li><strong>Server-signed payloads</strong> baked during <code>./build-site.sh</code>, so the console still deploys as static files but HTMX consumes fresh data snapshots generated minutes before publish.</li>
  44. <li><strong>Composable EJS partials</strong> that keep styling consistent across the console, docs, and blog while letting us drop in context-sensitive callouts.</li>
  45. <li><strong>Telemetry hooks</strong> that emit lightweight events for interaction patterns, giving us benchmarks on what readers actually open.</li>
  46. </ul>
  47. <h3>Improvements we’re seeing now</h3>
  48. <ul>
  49. <li><strong>Faster refresh cadence:</strong> Regenerating the JSON snapshots is ~12× faster than rebuilding the full HTML tree, which cut publish latency from ~9 minutes to well under a minute for most pushes.</li>
  50. <li><strong>Unified filtering:</strong> Repo search, tag filters, and changelog toggles now live in a single HTMX-driven control bar, replacing the stitched-on JavaScript and making keyboard navigation reliable.</li>
  51. <li><strong>Consistent accessibility:</strong> We aligned aria roles and focus management across the console because HTMX lets us target fragments instead of whole pages, eliminating the tab-trap issues we had with Stagit modals.</li>
  52. <li><strong>Editorial flexibility:</strong> Because the console renders from JSON, we can append release summaries, attach post links, or flag breaking changes without editing C templates or rebuilding binary tooling.</li>
  53. </ul>
  54. <h3>What’s next</h3>
  55. <p>The HTMX system isn’t “set and forget.” We still snapshot git data during build time, so truly real-time commit streams remain on the backlog. We’re also experimenting with progressive enhancement that streams the top commit diff as Markdown for readers on low-bandwidth connections. If you depended on the older Stagit pages, their frozen copies remain archived under <code>/legacy/stagit/</code> for reference, but the console of record now lives entirely in the HTMX pipeline.</p>
