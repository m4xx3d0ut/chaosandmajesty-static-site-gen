Add **Flagger** to your existing **platform-config** GitOps repo, wired to your stack (NGINX Ingress + kube-prometheus-stack).

Using Flux’s **OCI Helm repo** for Flagger (recommended) and letting the Helm chart create its own CRD. I’ll also point Flagger at your Prometheus (`kube-prometheus-stack-prometheus.monitoring:9090`).

---

# 1) Add Flagger’s Helm source (OCI)

**File:** `clusters/microk8s-prod/infra/core/helmrepo-flagger.yaml`

```yaml
apiVersion: source.toolkit.fluxcd.io/v1
kind: HelmRepository
metadata:
  name: flagger-charts
  namespace: flux-system
spec:
  interval: 1m
  type: oci
  url: oci://ghcr.io/fluxcd/charts
```

> Using the OCI chart is the Flux/Flagger-docs path for GitOps installs. ([docs.flagger.app][1])

Make sure your existing `clusters/microk8s-prod/infra/core/kustomization.yaml` includes this new file in `resources:`.

---

# 2) Create a Flagger app folder under `gitops/apps`

```
gitops/apps/flagger/
  kustomization.yaml
  namespace.yaml
  release.yaml
```

**`gitops/apps/flagger/namespace.yaml`**

```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: flagger-system
```

**`gitops/apps/flagger/release.yaml`** (HelmRelease)

```yaml
apiVersion: helm.toolkit.fluxcd.io/v2
kind: HelmRelease
metadata:
  name: flagger
  namespace: flagger-system
spec:
  interval: 5m
  targetNamespace: flagger-system
  install:
    createNamespace: true
    crds: Create         # let Helm install Flagger's CRD
  upgrade:
    crds: Create
  chart:
    spec:
      chart: flagger
      version: ">=1.32.0"   # or pin a specific version
      sourceRef:
        kind: HelmRepository
        name: flagger-charts
        namespace: flux-system
  values:
    meshProvider: nginx
    metricsServer: "http://kube-prometheus-stack-prometheus.monitoring:9090"
    logLevel: info
```

* Flagger’s chart exposes `meshProvider` and `metricsServer`; setting `crds` for install/upgrade is supported by Flux Helm controller. ([fluxcd.io][2])
* You can install Flagger **in any namespace** so long as it can reach Prometheus on 9090. ([docs.flagger.app][3])

**`gitops/apps/flagger/kustomization.yaml`**

```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - namespace.yaml
  - release.yaml
```

Now add `./flagger` to your existing `gitops/apps/kustomization.yaml` so it’s picked up with the rest of your apps.

---

# 3) Include in cluster Kustomizations

If your `clusters/microk8s-prod/kustomizations/apps.yaml` already points at `./gitops/apps`, no change needed.
Otherwise, add a dedicated Kustomization:

**`clusters/microk8s-prod/kustomizations/flagger.yaml`**

```yaml
apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization
metadata:
  name: flagger
  namespace: flux-system
spec:
  interval: 1m
  sourceRef:
    kind: GitRepository
    name: flux-system
  path: ./gitops/apps/flagger
  prune: true
  wait: true
  timeout: 5m
  dependsOn:
    - name: infra-core    # ensures helm repos & ingress exist
    - name: infra-crds    # if you keep CRDs separate, keep this
```

And reference `flagger.yaml` from your aggregator `clusters/microk8s-prod/kustomizations/kustomization.yaml` (or add it to `apps.yaml` if that’s your pattern).

---

# 4) Ensure NGINX & Prometheus are ready

* **Prometheus URL** used above is the kube-prometheus-stack default service name in `monitoring`. If yours differs, swap accordingly. Flagger queries Prometheus for built-in success-rate/latency checks. ([docs.flagger.app][4])
* **NGINX ingress metrics** should be enabled & scraped by Prometheus (controller metrics on, ServiceMonitor or scrape annotations). If you need it, enable:

  * `controller.metrics.enabled=true` and either `controller.metrics.serviceMonitor.enabled=true` (if you use Prom Operator) or `prometheus.io/scrape` annotations. ([DigitalOcean][5])

# 6) Verify in-cluster

```bash
# Verify Flagger connectivity to Prometheus (HTTP test - more reliable)
kubectl -n flagger-system exec deploy/flagger-system-flagger -- wget -qO- http://kube-prom-prometheus.monitoring:9090/api/v1/query?query=up

# Check Flagger logs for successful connection
kubectl -n flagger-system logs deploy/flagger-system-flagger | grep "Connected to metrics server"
```

If the HelmRelease fails to reconcile, check the HelmRelease events and logs from `helm-controller` in `flux-system`.

# 7) (Optional) Flagger loadtester

You can deploy the loadtester anywhere (often in the **same namespace as the app**, e.g., `ai`). We already included a loadtester manifest in the AI repo templates; if you want a “global” one managed by platform-config:

**`gitops/apps/flagger/loadtester.yaml`**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: flagger-loadtester
  namespace: flagger-system
spec:
  replicas: 1
  selector:
    matchLabels: { app: flagger-loadtester }
  template:
    metadata:
      labels: { app: flagger-loadtester }
    spec:
      containers:
        - name: loadtester
          image: ghcr.io/fluxcd/flagger-loadtester:0.26.1
          ports:
            - name: http
              containerPort: 8080
---
apiVersion: v1
kind: Service
metadata:
  name: flagger-loadtester
  namespace: flagger-system
spec:
  selector:
    app: flagger-loadtester
  ports:
    - name: http
      port: 80
      targetPort: 8080
```
