        <h1>LLMOps Checklist &amp; K8s Templates (Flux + LEANN)</h1>
<p><strong>Target stack:</strong> MicroK8s + Flux GitOps, NGINX Ingress, Prometheus/Grafana/Tempo/Loki/Mimir (or Grafana Alloy as the OTLP collector), NVIDIA GPU node(s) optional, LEANN workers for edge-aware RAG.</p>
<blockquote>
<p>📌 <strong>Conventions</strong></p>
<ul>
<li>Namespace: <code>ai</code></li>
<li>Your local registry: <code>reg.microk8s.core.home.arpa:32000</code></li>
<li>Alloy OTLP endpoint: <code>alloy.monitoring.svc.cluster.local:4317</code></li>
<li>Prometheus: <code>kube-prometheus-stack-prometheus.monitoring:9090</code> (adjust if different)</li>
<li>Ingress class: <code>nginx</code></li>
<li>Apps: <code>gateway</code> (FastAPI/HTTP), <code>retriever</code> (RAG service), <code>leann-worker</code> (GPU optional)</li>
</ul>
<p>Replace image names and env with your own.</p>
</blockquote>

  template:
    metadata:
      labels:
        app.kubernetes.io/name: gateway
      annotations:
        checksum/routing: &quot;{{sha256 of routing.yaml if templated}}&quot;
        checksum/flags: &quot;{{sha256 of flags.yaml if templated}}&quot;
    spec:
      serviceAccountName: default
      containers:
        - name: gateway
          image: reg.microk8s.core.home.arpa:32000/ai/gateway:1.0.0

            - name: ROUTING_PATH

              value: /config/flags.yaml

              value: /schemas
            - name: OTEL_SERVICE_NAME
              value: gateway
            - name: OTEL_TRACES_SAMPLER
              value: parentbased_traceidratio

                name: otel-resource

<h2>6) Flagger Canary for <code>gateway</code> (with NGINX provider)</h2>
<blockquote>
<p>Assumes Flagger and Prometheus are installed. If not, install Flagger (Helm) and apply <code>loadtester.yaml</code> below.</p>
</blockquote>
<pre><code class="language-yaml"># k8s/base/flagger/canary-gateway.yaml
apiVersion: flagger.app/v1beta1
kind: Canary
metadata:
  name: gateway
  namespace: ai
spec:
  provider: nginx
  # Prometheus address used by Flagger for built-in SLOs
  metricsServer: http://kube-prometheus-stack-prometheus.monitoring:9090
  targetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: gateway
  service:
    port: 8080
    # Optional: enable session stickiness, headers, etc.
  analysis:
    interval: 1m
    threshold: 10           # max number of failed checks before rollback
    iterations: 10          # total checks before promotion
    maxWeight: 50           # canary traffic percentage
    stepWeight: 10          # increase every iteration
    metrics:
      - name: request-success-rate
        thresholdRange:
          min: 99
        interval: 1m
      - name: request-duration
        thresholdRange:
          max: 1000
        interval: 30s
    webhooks:
      - name: load-test
        type: pre-rollout
        url: http://flagger-loadtester.ai/
        timeout: 10s
        metadata:
          cmd: &quot;hey -z 45s -q 10 -c 2 http://gateway.ai:8080/healthz&quot;
</code></pre>

<h2>9) Notes on OTel wiring with Grafana Alloy</h2>
<ul>
<li>This template sets <code>OTEL_EXPORTER_OTLP_ENDPOINT</code> via <code>config-otel-resource.yaml</code> to the Alloy service in <code>monitoring</code> ns (<code>alloy.monitoring.svc.cluster.local:4317</code>).</li>
<li>Ensure Alloy is configured to <strong>receive</strong> OTLP (traces/metrics/logs) and <strong>export</strong> traces to Tempo, metrics to Prometheus Remote Write (or scrape), logs to Loki.</li>
<li>If you don’t run Alloy, point <code>OTEL_EXPORTER_OTLP_ENDPOINT</code> at Tempo (traces) and at your metrics/logs pipeline accordingly.</li>
</ul>
<hr>
<h2>10) Promotion workflow (how to canary a new version)</h2>
<ol>
<li>Update the container tag for <code>gateway</code> in <code>k8s/base/gateway/deploy.yaml</code> (e.g., <code>1.0.1</code>).</li>
<li>Commit &amp; push to your Flux repo branch tracked by <code>flux-system</code>.</li>
<li>Watch Flagger analysis: <code>kubectl -n ai describe canary gateway</code> and <code>kubectl -n ai get ev --watch</code>.</li>
<li>If metrics hold, Flagger promotes; on failures, it rolls back.</li>
</ol>

<p>Your workstation probably can’t resolve <code>*.svc.cluster.local</code>. Generate the host key from a pod that <strong>can</strong>:</p>
<pre><code class="language-bash"># Use the source-controller pod (Alpine-based) to scan the SSH service
kubectl -n flux-system exec deploy/source-controller -- sh -c \
  &quot;apk add -q openssh-client || true; ssh-keyscan -p 2222 gitea-ssh.git-local.svc.cluster.local&quot; \
  | tee known_hosts
</code></pre>
<blockquote>
<p>Alternative: run a short‑lived toolbox pod (<code>kubectl run -it toolbox --rm --image=alpine -- sh</code>) and run <code>ssh-keyscan -p 32222 gitea.core.home.arpa</code> inside it, then copy the output.</p>
</blockquote>
<h3>2.3 Create the Secret in <code>flux-system</code></h3>
<pre><code class="language-bash">kubectl -n flux-system create secret generic ai-system-ssh \
  --from-file=identity=./flux-ai-ai-system \
  --from-file=identity.pub=./flux-ai-ai-system.pub \
  --from-file=known_hosts=./known_hosts
</code></pre>

<h2>3) Add Flux <strong>GitRepository</strong> + <strong>Kustomization</strong> (in monorepo)</h2>
<p>Create two files in your <strong>platform-config</strong> repo so Flux can reconcile the new repo.</p>
<h3>3.1 GitRepository (source)</h3>
<p><code>clusters/microk8s-prod/flux-system/gitrepository-ai-system.yaml</code></p>
<pre><code class="language-yaml">apiVersion: source.toolkit.fluxcd.io/v1
kind: GitRepository
metadata:
  name: ai-system
  namespace: flux-system
spec:
  interval: 1m
  url: ssh://git@gitea-ssh.git-local.svc.cluster.local:2222/m4xx3d0ut/ai-system-config.git

  secretRef:
    name: ai-system-ssh

<h3>3.2 Kustomization (reconciler)</h3>

<pre><code class="language-yaml">apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization
metadata:
  name: ai-system
  namespace: flux-system

    - name: infra-core

      kind: Deployment

      namespace: ai

<h3>3.3 Include these in your aggregator</h3>
<p>Add the new files to your existing aggregator kustomization so Flux applies them:</p>
<p><code>clusters/microk8s-prod/kustomizations/kustomization.yaml</code> (example)</p>

  - infra-core.yaml
  - infra-crds.yaml
  - infra-policies.yaml

        clusters/microk8s-prod/kustomizations/ai-system.yaml \

<h2>4) First reconcile &amp; validation</h2>
<pre><code class="language-bash"># Check the source and kustomization

kubectl -n flux-system describe kustomization ai-system

# Verify workloads

<p>If the <code>GitRepository</code> is failing:</p>
<ul>
<li><strong>host key mismatch</strong> → regenerate <code>known_hosts</code> from inside cluster and recreate the secret.</li>
<li><strong>permission denied</strong> → ensure deploy key is added to the repo and has <strong>Read</strong> access.</li>
<li><strong>network</strong> → ensure <code>flux-system</code> pods can resolve and reach <code>gitea-ssh.git-local.svc.cluster.local:2222</code>.</li>
</ul>

<h2>5) SOPS (optional, recommended)</h2>
<p>If you encrypt secrets in <code>ai-system-config</code>:</p>
<ol>
<li>Reuse the same <strong>age</strong> keypair that your monorepo uses.</li>
<li>Commit <code>.sops.yaml</code> in <code>ai-system-config</code> with the public key.</li>

<ul>
<li>Prepare changes on <code>main</code> in <code>ai-system-config</code> → create tag <code>v1.0.0</code> → update or let an automated policy bump the tag in the <strong>monorepo</strong> <code>gitrepository-ai-system.yaml</code> → Flux promotes.</li>
</ul>

<h2>8) Troubleshooting quick hits</h2>
<ul>
<li><p><strong>GitRepository stuck</strong> <code>auth/ssh: handshake failed</code>: wrong key in secret or SSH service not reachable; verify with:</p>
<pre><code class="language-bash">kubectl -n flux-system exec deploy/source-controller -- sh -c \
  &quot;apk add -q openssh-client || true; ssh -p 2222 -o StrictHostKeyChecking=yes git@gitea-ssh.git-local.svc.cluster.local -T&quot; || true
</code></pre>
</li>
<li><p><strong>Kustomization <code>not ready</code></strong>: run <code>describe</code> to see the failing object; often missing CRDs (Flagger, Prometheus). Ensure your <code>dependsOn</code> brings them up first.</p>
</li>
<li><p><strong>Ingress 404</strong>: confirm DNS for <code>gateway.core.home.arpa</code> (or your host), check NGINX Ingress logs, and that the Service <code>gateway</code> is Healthy.</p>
</li>
<li><p><strong>No traces/metrics</strong>: verify Alloy OTLP endpoint in <code>config-otel-resource.yaml</code> and NetworkPolicy egress paths to <code>monitoring</code> ns.</p>
</li>
</ul>

<h3>Summary</h3>
<p>You now have a clean <strong>split‑repo</strong> setup: platform Flux config stays in the monorepo, while <code>ai-system-config</code> owns the AI stack. Flux pulls via <strong>in‑cluster SSH</strong> at <code>gitea-ssh.git-local.svc.cluster.local:2222</code>, with a scoped deploy key and pinned <code>known_hosts</code>. Promotion and rollback are controlled from the monorepo by tweaking the <code>GitRepository</code> ref, while day‑to‑day app evolution happens in the dedicated repo.</p>

<h2>Golden config (Turing-safe vLLM block)</h2>
<p>Drop this into your <code>Deployment</code> <strong>container: vllm</strong> (it matches what worked for you):</p>
<pre><code class="language-yaml"># container: vllm
image: vllm/vllm-openai:latest-x86_64
args:
  - --port; &quot;8000&quot;
  - --model; &quot;zai-org/glm-edge-1.5b-chat&quot;
  - --download-dir; /models
  - --tensor-parallel-size; &quot;1&quot;
  - --dtype; float16                # no BF16 on SM 7.5
env:
  - name: HUGGING_FACE_HUB_TOKEN
    valueFrom:
      secretKeyRef:
        name: hf-token
        key: HUGGING_FACE_HUB_TOKEN
        optional: true
  - { name: VLLM_PORT, value: &quot;39000&quot; }                 # avoid K8s URI collision
  - { name: VLLM_USE_FLASHINFER, value: &quot;0&quot; }           # disable FlashInfer sampler on Turing
ports:
  - { name: openai, containerPort: 8000 }
resources:
  requests: { cpu: &quot;4&quot;, memory: &quot;20Gi&quot;, nvidia.com/gpu: &quot;1&quot; }
  limits:   { cpu: &quot;8&quot;, memory: &quot;40Gi&quot;, nvidia.com/gpu: &quot;1&quot; }
volumeMounts:
  - { name: hf-cache, mountPath: /models }
# be patient during compile/warmup
startupProbe:
  httpGet: { path: /health, port: openai }
  periodSeconds: 5
  timeoutSeconds: 2
  failureThreshold: 60       # ~5 min
readinessProbe:
  httpGet: { path: /health, port: openai }
  initialDelaySeconds: 10
  periodSeconds: 5
  timeoutSeconds: 1
livenessProbe:
  httpGet: { path: /health, port: openai }
  initialDelaySeconds: 60
  periodSeconds: 10
  timeoutSeconds: 2
</code></pre>
<p>And at the <strong>pod</strong> level:</p>
<pre><code class="language-yaml">spec:
  enableServiceLinks: false          # stop injecting VLLM_* from Service
  runtimeClassName: nvidia
  nodeSelector: { accelerator: nvidia }
</code></pre>

<h2>NetworkPolicy must-haves</h2>
<p>Allow the basics so vLLM can resolve and fetch models, and so gateway ↔ vLLM works:</p>
<pre><code class="language-yaml"># default deny (Ingress+Egress) for safety
---
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: { name: default-deny, namespace: ai }
spec: { podSelector: {}, policyTypes: [Ingress, Egress] }

# DNS egress (fast unbreak)
---
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: { name: allow-dns-any, namespace: ai }
spec:
  podSelector: {}
  policyTypes: [&quot;Egress&quot;]
  egress:
    - to: [ { ipBlock: { cidr: 0.0.0.0/0 } } ]
      ports:
        - { protocol: UDP, port: 53 }
        - { protocol: TCP, port: 53 }

# Internet egress for vllm/gateway (80/443)
---
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: { name: allow-egress-internet-for-ai, namespace: ai }
spec:
  podSelector:
    matchExpressions:
      - { key: app.kubernetes.io/name, operator: In, values: [&quot;vllm&quot;,&quot;gateway&quot;] }
  policyTypes: [&quot;Egress&quot;]
  egress:
    - to: [ { ipBlock: { cidr: 0.0.0.0/0 } } ]
      ports:
        - { protocol: TCP, port: 443 }
        - { protocol: TCP, port: 80 }

# east-west inside ai ns
---
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: { name: allow-ai-eastwest, namespace: ai }
spec:
  podSelector: {}
  policyTypes: [Ingress, Egress]
  ingress: [ { from: [ { podSelector: {} } ] } ]
  egress:  [ { to:   [ { podSelector: {} } ] } ]
</code></pre>
<p>(You can later tighten DNS to your CoreDNS labels/IPs.)</p>
