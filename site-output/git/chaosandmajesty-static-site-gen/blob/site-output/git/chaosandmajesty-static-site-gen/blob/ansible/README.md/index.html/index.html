  14. <h1>Chaos &amp; Majesty Ansible Deployment</h1>
  15. <p>This playbook deploys the production container image to the Linode VPS via SSH.</p>
  16. <h2>Layout</h2>
  17. <ul>
  18. <li><code>inventory/hosts.ini</code> – target hosts; override <code>ansible_host</code> before use.</li>
  19. <li><code>group_vars/all.yml</code> – defaults (install path, image coordinates, mounts).</li>
  20. <li><code>deploy.yml</code> – entrypoint playbook that applies the <code>app_deploy</code> role.</li>
  21. <li><code>requirements.yml</code> – Ansible collections required (<code>community.docker</code>).</li>
  22. <li><code>roles/app_deploy</code> – renders Docker Compose configuration and deploys the site container.</li>
  23. <li><code>../config/git/manifest.txt</code> – repository manifest consumed by the static site generator.</li>
  24. </ul>
  25. <h2>Usage</h2>
  26. <ol>
  27. <li>Install dependencies:<pre><code class="language-bash">ansible-galaxy collection install -r requirements.yml
  28. </code></pre>
  29. </li>
  30. <li>Provide the target host address by editing <code>inventory/hosts.ini</code> (defaults to
  31. <code>chaosandmajesty.com</code>) or by passing
  32. <code>-i &quot;prod,&quot; -e ansible_host=vps.example.com</code>.</li>
  33. <li>Supply the registry coordinates and credentials (if private):<pre><code class="language-bash">ansible-playbook -i inventory/hosts.ini deploy.yml \
  34. -e image_registry=ghcr.io \
  35. -e image_namespace=chaosandmajesty \
  36. -e image_name=cm-site \
  37. -e image_tag=prod
  38. </code></pre>
  39. </li>
  40. <li>When running from CI, export <code>REGISTRY_USERNAME</code>/<code>REGISTRY_PASSWORD</code> secrets
  41. and pass them via <code>-e registry_username=...</code> or environment variable lookup
  42. in the workflow.</li>
  43. </ol>
  44. <p>Key defaults (override in <code>group_vars/all.yml</code> or via extra-vars):</p>
  45. <ul>
  46. <li><code>webdav_host_path=/var/www/html/dav</code> keeps the host Joplin share mounted.</li>
  47. <li><code>letsencrypt_host_path=/etc/letsencrypt</code> shares existing certificates read-only.</li>
  48. <li><code>acme_webroot_host_path=/var/www/letsencrypt</code> is used for HTTP-01 challenges.</li>
  49. <li><code>auth_file_host_path=/etc/nginx/auth</code> mounts your existing WebDAV htpasswd directory read-only so credentials continue to work.</li>
  50. <li><code>disable_host_nginx=true</code> stops and disables the system nginx service at deploy time.</li>
  51. </ul>
  52. <p>The role will render a Docker Compose project in <code>{{ app_dir }}</code> (default
  53. <code>/opt/chaosandmajesty</code>), ensure the WebDAV directory exists on the host, pull the
  54. specified image, and recreate the container. A health check against
  55. <code>http://127.0.0.1:{{ healthcheck_port }}</code> guards against silent failures.</p>
  56. <h2>Git manifest</h2>
  57. <p>The static site generator consumes <code>config/git/manifest.txt</code> to know which
  58. repositories to mirror locally during <code>./build-site.sh</code>. Update that manifest
  59. before builds so the Git page sidebar stays in sync with your catalog.</p>
