  14. <h1>RadioStatic Demo Guide</h1>
  15. <p>This guide walks through the retro RadioStatic demo that ships with the repository. Follow it to generate the sample site locally, explore the output, and adapt the structure for your own projects.</p>
  16. <h2>Prerequisites</h2>
  17. <ul>
  18. <li>Node.js 18 or newer (the demo runs entirely on the command line—no extra services required)</li>
  19. <li><code>npm</code> for installing dependencies</li>
  20. <li>Optional: <code>make</code> for the convenience targets</li>
  21. </ul>
  22. <h2>1. Install Dependencies</h2>
  23. <pre><code class="language-bash">npm install
  24. </code></pre>
  25. <p>Installation is only required the first time you clone the repository (or after updating dependencies).</p>
  26. <h2>2. Build the Demo</h2>
  27. <pre><code class="language-bash">./build-site.sh
  28. </code></pre>
  29. <p>The script wraps the generator CLI (<code>static-sitegen/bin/radiostatic.js</code>) and defaults to <code>smoke-test.yaml</code>. It validates the resulting files and prints a short listing from the output directory.</p>
  30. <h3>Custom Configuration Names</h3>
  31. <p>You can pass a different configuration file or choose a custom output directory:</p>
  32. <pre><code class="language-bash">./build-site.sh config/your-site.yaml public-site
  33. </code></pre>
  34. <p>The script also respects environment variables (new names listed first, legacy aliases still work):</p>
  35. <ul>
  36. <li><code>RADIOSTATIC_CONFIG</code> / <code>SITEGEN_CONFIG</code> – default config path (overridden by positional argument)</li>
  37. <li><code>RADIOSTATIC_OUTPUT</code> / <code>SITEGEN_OUTPUT</code> – default output directory</li>
  38. <li><code>RADIOSTATIC_VERBOSE</code> / <code>SITEGEN_VERBOSE</code> – set to <code>0</code> to suppress verbose logging</li>
  39. </ul>
  40. <p><code>make build-local</code> supports the same options:</p>
  41. <pre><code class="language-bash">make build-local CONFIG=config/your-site.yaml OUTPUT=public-site
  42. </code></pre>
  43. <h2>3. Serve the Output</h2>
  44. <pre><code class="language-bash">make serve-local
  45. </code></pre>
  46. <p>This runs <code>python3 -m http.server 8080</code> inside the <code>site-output/</code> directory so you can browse the generated pages at <a href="http://localhost:8080">http://localhost:8080</a>.</p>
  47. <p>Stop the server with <code>Ctrl+C</code> when finished.</p>
  48. <h2>Demo Components</h2>
  49. <ul>
  50. <li><strong>Configuration</strong> – <code>smoke-test.yaml</code> demonstrates every supported feature (home page hero, sections, blog, sitemap).</li>
  51. <li><strong>Blog content</strong> – <code>content/blog/</code> contains Markdown posts for two sample authors (<code>alex-lee</code> and <code>jamie-hart</code>) plus a default article used by the blog landing page.</li>
  52. <li><strong>Assets</strong> – <code>examples/demo-site/assets/</code> holds the CSS, JavaScript, SVG artwork, <code>site.webmanifest</code>, and <code>robots.txt</code> referenced by the demo configuration.</li>
  53. <li><strong>Stagit sample</strong> – <code>examples/demo-site/stagit/</code> packages a small bare git repository and static HTML so you can illustrate a repository mirror alongside the site. Step-by-step integration lives in the <a href="#stagit-demo">Stagit</a> section below.</li>
  54. </ul>
  55. <h2>Updating Assets</h2>
  56. <p>To experiment with the assets that ship inside <code>static-sitegen/assets/</code>, run:</p>
  57. <pre><code class="language-bash">./prepare-demo-assets.sh
  58. </code></pre>
  59. <p>The script mirrors <code>examples/demo-site/assets/</code> into <code>static-sitegen/assets/</code> (useful when tweaking the default theme). Pass a different source directory if you maintain your own asset pack:</p>
  60. <pre><code class="language-bash">./prepare-demo-assets.sh path/to/your-assets
  61. </code></pre>
  62. <h2>Editing Content</h2>
  63. <ol>
  64. <li>Duplicate a post in <code>content/blog/</code> or create a new Markdown file.</li>
  65. <li>Update the front matter (<code>title</code>, <code>slug</code>, <code>author</code>, <code>publishedAt</code>, <code>heroImage</code>, etc.).</li>
  66. <li>Re-run <code>./build-site.sh</code> (or <code>make build-local</code>) to regenerate the site.</li>
  67. </ol>
  68. <p>Authors are configured in the YAML file under <code>blog.authors</code>. Add new entries to expose additional avatars, bios, and social links.</p>
  69. <h2>Stagit Demo</h2>
  70. <p>The demo includes:</p>
  71. <ul>
  72. <li><code>examples/demo-site/stagit/repos/hello-world.git</code> – a tiny bare repository with two commits.</li>
  73. <li><code>examples/demo-site/stagit/html/</code> – placeholder HTML styled to resemble a stagit export.</li>
  74. </ul>
  75. <p><code>smoke-test.yaml</code> declares an <code>extraCopies</code> entry so the build automatically mirrors the HTML folder into <code>site-output/stagit/</code>. Replace these artifacts with real stagit output when you connect your own repositories or point the <code>from</code> path at your own build pipeline.</p>
  76. <h2>Next Steps</h2>
  77. <ul>
  78. <li>Read <a href="configuration.md">docs/configuration.md</a> for a tour of the YAML keys and how they map to templates.</li>
  79. <li>Update the navigation links, sections, and call-to-action blocks in your configuration file to match your project.</li>
  80. <li>Swap the SVG artwork under <code>examples/demo-site/assets/static/img/</code> and rerun the build.</li>
  81. <li>Commit the resulting <code>site-output/</code> directory to the platform of your choice or upload it to static hosting.</li>
  82. </ul>
  83. <p>That’s it—you now have a working RadioStatic build and a clear path for customising it.</p>
