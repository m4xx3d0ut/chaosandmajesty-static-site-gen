  14. <h1>DOOM WASM Integration</h1>
  15. <p>This project embeds the shareware build of DOOM inside the console minigame. The
  16. runtime expects the wasm binary (<code>doom.wasm</code>) under
  17. <code>static-sitegen/assets/doom/</code>.</p>
  18. <h2>Building the assets</h2>
  19. <ol>
  20. <li>Run <code>./scripts/build-doom.sh</code>. By default the script downloads the published
  21. wasm artefact from the
  22. <a href="https://diekmann.github.io/wasm-fizzbuzz/doom/">wasm-fizzbuzz GitHub Pages</a>.<ul>
  23. <li>Set <code>DOOM_SOURCE_DIR</code> to copy from a local checkout (after building the
  24. wasm artefact yourself).</li>
  25. <li>Set <code>DOOM_WASM_URL</code> to override the download location.</li>
  26. </ul>
  27. </li>
  28. <li>Re-run <code>./build-site.sh</code> (or <code>ENABLE_DOOM_BUILD=1 ./build-site.sh</code> to let the
  29. build invoke the helper automatically) and <code>make serve-local</code>. Launch
  30. <code>play doom</code> from the console to verify.</li>
  31. </ol>
  32. <h2>Runtime notes</h2>
  33. <ul>
  34. <li>The loader looks under <code>assets/doom/</code> relative to the current page. Override
  35. <code>window.cmDoomConfig.assetBase</code> if you host the assets elsewhere.</li>
  36. <li>WebAssembly support, audio auto-play, and performance vary across devices.
  37. The terminal prints a friendly message when the browser is unsupported.</li>
  38. <li><code>exit doom</code> tears down the game and restores the terminal display.</li>
  39. </ul>
  40. <h2>Licensing</h2>
  41. <ul>
  42. <li>The original DOOM shareware data is © id Software. Ensure you only ship the
  43. redistributable shareware WAD when sharing builds.</li>
  44. <li>The wasm port inherits the GPL/other licensing from the upstream project.
  45. Consult the upstream repo for details.</li>
  46. </ul>
  47. <h2>Source provenance &amp; GPL compliance</h2>
  48. <ul>
  49. <li>Upstream engine sources come from <a href="https://github.com/diekmann/wasm-fizzbuzz"><code>diekmann/wasm-fizzbuzz</code></a>
  50. (the <code>doom/</code> directory) at commit <code>51a7030bea563d96027301a36619c17347b9270d</code>.</li>
  51. <li>Chaos &amp; Majesty specific changes (audio worklet bridge, save-system hooks,
  52. toolchain upgrades, and music playback) are recorded in
  53. <code>static-sitegen/assets/doom/patches/0001-chaos-and-majesty-doom-wasm.patch</code>.</li>
  54. <li>The repository ships the GPL text as <code>COPYING</code>. Keep that file with every
  55. distribution that includes <code>doom.wasm</code>.</li>
  56. </ul>
  57. <p>Whenever you change the engine or supporting runtime, update the patch file and
  58. add a short bullet to this section noting the change and date.</p>
  59. <h2>Regenerating <code>doom.wasm</code> from source</h2>
  60. <p>The build depends on Rust (with the <code>wasm32-unknown-unknown</code> target installed),
  61. clang/llvm 12, Binaryen’s <code>wasm-opt</code>, and the DOOM shareware WAD (not included).</p>
  62. <ol>
  63. <li>Clone the upstream repo and check out the recorded commit:<pre><code class="language-bash">git clone https://github.com/diekmann/wasm-fizzbuzz.git
  64. cd wasm-fizzbuzz/doom
  65. git checkout 51a7030bea563d96027301a36619c17347b9270d
  66. </code></pre>
  67. </li>
  68. <li>Apply the Chaos &amp; Majesty patch bundle:<pre><code class="language-bash">git apply /path/to/static-sitegen/assets/doom/patches/0001-chaos-and-majesty-doom-wasm.patch
  69. </code></pre>
  70. </li>
  71. <li>Provide <code>doom1.wad</code> (shareware data) next to the Makefile. The patch keeps
  72. the WAD unmodified; fetch it from the official shareware drop.</li>
  73. <li>Build:<pre><code class="language-bash">rustup target add wasm32-unknown-unknown
  74. make doom.wasm
  75. </code></pre>
  76. Or run the helper script which encapsulates the steps above (including
  77. Binaryen download):<pre><code class="language-bash">DOOM_WAD_PATH=/absolute/path/to/doom1.wad ./scripts/rebuild-doom.sh
  78. </code></pre>
  79. </li>
  80. <li>Copy the resulting <code>doom.wasm</code> into <code>static-sitegen/assets/doom/</code> and keep
  81. the patched source tree archived (e.g., <code>tar czf doom-source.tar.gz doom/</code>)
  82. alongside any distributed binaries.</li>
  83. </ol>
  84. <h2>Release checklist</h2>
  85. <ul>
  86. <li>Include <code>COPYING</code> and the source archive (or a public URL that serves it) in
  87. the same place you publish <code>doom.wasm</code>.</li>
  88. <li>Update <code>static-sitegen/assets/doom/patches/</code> whenever you modify the engine.</li>
  89. <li>Verify <code>docs/doom.md</code> references the correct commit hash and patch filename.</li>
  90. </ul>
