# Source of Truth — NVIDIA GPU Operator on MicroK8s

**Model:** Quadro RTX 8000 • **OS:** Ubuntu 22.04 (jammy) • **CRI:** containerd (MicroK8s)
**Policy:** runc stays default; NVIDIA runtime is **opt-in** via `runtimeClassName`
**vGPU/GRID:** **not** used in this cluster

> MicroK8s containerd lives under the snap:
>
> * socket: `/var/snap/microk8s/common/run/containerd.sock` ([kb.brightcomputing.com][1])
> * config template: `/var/snap/microk8s/current/args/containerd-template.toml` (MicroK8s rewrites actual config from this template).

---

## Goals & Decisions

* Keep **runc** as cluster default.
* Use **RuntimeClass** to opt-in GPU runtime per workload.
* Manage the stack with **GPU Operator** (Helm via Flux).
* Prefer **host-managed toolkit** (simpler on MicroK8s), with an **operator-managed** path documented as an alternative.
* (Optional) Guardrail policy that **denies** GPU workloads missing the RuntimeClass.

Repo layout (excerpt):

```
clusters/microk8s-prod/infra/core/     # Helm repos, RuntimeClasses, cluster infra
gitops/apps/gpu-operator/              # HelmRelease & namespace
infra-policies/                        # admission policies (optional)
```

## Prereqs (host)

* NVIDIA driver present (`nvidia-smi` OK).
* `nvidia-container-toolkit` (and `libnvidia-container*`) installed from packages.
* CRI sanity:

  ```bash
  # recommended: /etc/crictl.yaml
  sudo tee /etc/crictl.yaml >/dev/null <<'EOF'
  runtime-endpoint: unix:///var/snap/microk8s/common/run/containerd.sock
  image-endpoint:   unix:///var/snap/microk8s/common/run/containerd.sock
  timeout: 10
  debug: false
  EOF

  sudo crictl info | jq -r '.config.containerd.defaultRuntimeName'   # expect: runc
  sudo crictl info | jq '.config.containerd.runtimes | keys'          # expect includes: "nvidia-container-runtime"
  ```

## 2) RuntimeClass (opt-in)

We standardize on **`nvidia-container-runtime`** (matches the handler you already expose in containerd).

**File:** `clusters/microk8s-prod/infra/core/runtimeclass-nvidia-container-runtime.yaml`

```yaml
apiVersion: node.k8s.io/v1
kind: RuntimeClass
metadata:
  name: nvidia-container-runtime
handler: nvidia-container-runtime
```

> The GPU Operator can also create a `RuntimeClass nvidia` by default. We don’t rely on it. If you want to support both during transition, keep both RuntimeClasses.

## 3) GPU Operator (HelmRelease)

### Choose **ONE** of the following deployment patterns.

#### A) **Recommended (MicroK8s-friendly): Host-managed toolkit**

Skip the operator’s toolkit DaemonSet. Use the toolkit already on the host and the containerd runtime you have.

**File:** `gitops/apps/gpu-operator/release.yaml`

```yaml
apiVersion: helm.toolkit.fluxcd.io/v2
kind: HelmRelease
metadata:
  name: gpu-operator
  namespace: gpu-operator-resources
spec:
  interval: 30m
  chart:
    spec:
      chart: gpu-operator
      version: "*"
      sourceRef:
        kind: HelmRepository
        name: nvidia
        namespace: flux-system
  values:
    # Skip containerd edits; use host toolkit/runtime
    toolkit:
      enabled: false

    # Keep runc default; operator runs on containerd
    operator:
      defaultRuntime: containerd

    # Core components we want
    devicePlugin:
      enabled: true
    dcgmExporter:
      enabled: true
```

#### B) **Alternative: Operator-managed toolkit (pin a safe chart)**

If you prefer the operator to configure the runtime class and signal containerd, set envs to MicroK8s paths **and pin** to a chart version that honors them (e.g., `v25.3.0`). There’s a regression in `v25.3.3` where `CONTAINERD_SOCKET` is ignored, causing `/runtime/sock-dir/containerd.sock` errors; pin or work around. ([docs.rafay.co][2])

```yaml
# gitops/apps/gpu-operator/release.yaml
apiVersion: helm.toolkit.fluxcd.io/v2
kind: HelmRelease
metadata:
  name: gpu-operator
  namespace: gpu-operator-resources
spec:
  interval: 30m
  chart:
    spec:
      chart: gpu-operator
      version: "v25.3.0"     # pin a known-good
      sourceRef:
        kind: HelmRepository
        name: nvidia
        namespace: flux-system
  values:
    toolkit:
      enabled: true
      env:
        - name: CONTAINERD_CONFIG
          value: /var/snap/microk8s/current/args/containerd-template.toml
        - name: CONTAINERD_SOCKET
          value: /var/snap/microk8s/common/run/containerd.sock
        - name: CONTAINERD_RUNTIME_CLASS
          value: nvidia-container-runtime
        - name: CONTAINERD_SET_AS_DEFAULT
          value: "false"
    operator:
      defaultRuntime: containerd
    devicePlugin:
      enabled: true
    dcgmExporter:
      enabled: true
```

> What those envs do (from NVIDIA docs): configure which runtime class name to create and which containerd config/socket to touch; default runtime class name is `nvidia` if you don’t set it.

**Namespace & wiring**

```yaml
# gitops/apps/gpu-operator/namespace.yaml

  name: gpu-operator-resources
```

```yaml

  # ...existing
  - gpu-operator/namespace.yaml
```

## 4) (Optional) Guardrail — require RuntimeClass when requesting GPUs

**Disable by default.** Turn on after everything is stable.

**File:** `infra-policies/require-nvidia-runtimeclass.yaml`

```yaml
apiVersion: admissionregistration.k8s.io/v1
kind: ValidatingAdmissionPolicy
metadata:
  name: require-nvidia-runtimeclass
spec:
  failurePolicy: Fail
  matchConstraints:
    resourceRules:
      - apiGroups: ["", "apps", "batch"]
        apiVersions: ["*"]
        operations: ["CREATE","UPDATE"]
        resources: ["pods","deployments","statefulsets","daemonsets","jobs","cronjobs"]
  validations:
    - expression: |
        // Normalize to a PodSpec for Pods vs controllers
        let ps = has(object.spec.template) ? object.spec.template.spec : object.spec;

        // Is any container requesting GPUs?
        let gpu_requested = has(ps.containers) && ps.containers.exists(c,
          has(c.resources) && has(c.resources.limits) &&
          ("nvidia.com/gpu" in c.resources.limits)
        );

        // If GPUs are requested, require one of our RuntimeClasses
        !gpu_requested ||
        (has(ps.runtimeClassName) &&
          (ps.runtimeClassName == "nvidia-container-runtime" ||
           ps.runtimeClassName == "nvidia"))
      message: "GPU workloads must set spec.runtimeClassName to 'nvidia-container-runtime' (preferred) or 'nvidia'."
---
apiVersion: admissionregistration.k8s.io/v1
kind: ValidatingAdmissionPolicyBinding
metadata:
  name: require-nvidia-runtimeclass-binding
spec:
  policyName: require-nvidia-runtimeclass
  validationActions: ["Deny"]
```

**Enable/disable via Flux**

* **Enable:** add the file to `infra-policies/kustomization.yaml`
* **Disable:** `git rm infra-policies/require-nvidia-runtimeclass.yaml` and remove the line from the kustomization; ensure your Kustomization has `spec.prune: true` so Flux deletes it.

## 6) Troubleshooting (symptoms → fixes)

### A) `nvidia-container-toolkit-daemonset` CrashLooping with:

`unable to dial: dial unix /runtime/sock-dir/containerd.sock: no such file or directory`

* **Cause:** Operator’s toolkit can’t see MicroK8s’ containerd socket. In `v25.3.3` the `CONTAINERD_SOCKET` env may be ignored. ([docs.rafay.co][2])
* **Fix (pick one):**

  * **Recommended:** Use **host-managed** toolkit (`toolkit.enabled: false`). No containerd SIGHUP required.
  * **Or:** **Pin chart** to `v25.3.0` where the envs are honored; keep the `CONTAINERD_*` env set to the MicroK8s paths.
* **Verify:**

  ```bash
  kubectl -n gpu-operator-resources logs ds/nvidia-container-toolkit-daemonset --tail=100
  sudo crictl info | jq -r '.config.containerd.defaultRuntimeName'   # runc
  ```

### B) GPU pods denied by policy

* You enabled the guardrail but forgot `runtimeClassName`.
* Add `runtimeClassName: nvidia-container-runtime` **or** remove the policy via Flux (ensure prune).

### C) `nvidia-device-plugin` / `gpu-feature-discovery` stuck in `Init:0/1`

* Check operator log for “daemonset not ready” lines:

  ```bash
  kubectl -n gpu-operator-resources logs -l app.kubernetes.io/name=gpu-operator --tail=200
  ```
* Ensure driver is healthy:

  ```bash
  nvidia-smi
  lsmod | grep nvidia
  ```
* Ensure the node advertises GPUs (see Smoke tests).

### D) Containerd default was flipped to NVIDIA

* Re-assert default on host:

  ```bash
  sudo sed -i 's/^RUNTIME=.*/RUNTIME="runc"/' /var/snap/microk8s/current/args/containerd-env
  microk8s stop && microk8s start
  sudo crictl info | jq -r '.config.containerd.defaultRuntimeName'  # runc
  ```
* Ensure Helm values **do not** set “set as default”:

  * `CONTAINERD_SET_AS_DEFAULT: "false"`
  * `operator.defaultRuntime: containerd`
