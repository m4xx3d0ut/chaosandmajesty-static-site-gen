  18. <h1>PEN-200 Module 24 — Assembling the Pieces</h1>
  19. <h2>TLDR;</h2>
  20. <p>The “Assembling the Pieces” lab is a miniature red-team engagement. These enriched notes trace the full path captured in the raw journal so you can reproduce it intentionally.</p>
  21. <h3>External Recon &amp; Entry</h3>
  22. <ul>
  23. <li>Identify exposed hosts (<code>MAILSRV1</code>, <code>WEBSRV1</code>) with <code>nmap -sV -p 25,80,443</code>. Document banner versions and TLS posture.</li>
  24. <li>Enumerate WordPress on <code>WEBSRV1</code> with <code>wpscan --enumerate ap,vt --plugins-detection aggressive</code> ➜ vulnerable plugin leads to file upload RCE.</li>
  25. <li>Capture web shell callback details (timestamp, source IP, credentials harvested).</li>
  26. </ul>
  27. <h3>Establish Internal Foothold</h3>
  28. <ul>
  29. <li>Pivot through VPN/SSH using stolen credentials; log connection method.</li>
  30. <li>Run situational awareness: <code>whoami</code>, <code>ipconfig</code>, <code>net view</code>, <code>arp -a</code>, <code>nltest /dclist</code>.</li>
  31. <li>Map internal subnets and note interesting services (SQL, SMB shares, RDP gateways).</li>
  32. </ul>
  33. <h3>Credential Escalation</h3>
  34. <ul>
  35. <li>Phish internal user (e.g., <code>mike</code>) using crafted email + <code>.library-ms</code> payload. Record mail logs and the time of execution.</li>
  36. <li>Kerberoast service accounts: <code>Invoke-Kerberoast</code> ➜ crack <code>backupuser</code> password.</li>
  37. <li>Leverage captured credentials to access <code>CLIENT75</code>, dump additional hashes (<code>mimikatz sekurlsa::logonpasswords</code>).</li>
  38. </ul>
  39. <h3>Lateral Movement &amp; Domain Control</h3>
  40. <ul>
  41. <li>Relay Net-NTLMv2 to escalate privileges (<code>ntlmrelayx.py</code>).</li>
  42. <li>RDP into <code>DC01</code> as <code>backupuser</code>, collect domain admin privileges, create shadow copy for data access.</li>
  43. <li>Document each pivot with proof commands and note cleanup actions (delete payloads, remove scheduled tasks).</li>
  44. </ul>
  45. <h3>Reporting Narrative</h3>
  46. <ol>
  47. <li>Initial compromise via WordPress plugin upload.</li>
  48. <li>Credential harvesting through phishing ➜ reuse on internal hosts.</li>
  49. <li>Kerberoast ➜ <code>backupuser</code> ➜ domain admin privileges.</li>
  50. <li>Data access via shadow copies and share enumeration.</li>
  51. </ol>
  52. <p>Pair each step with evidence (hashes, command output, screenshots) and remediation guidance (patch plugin, enforce MFA, monitor Kerberos events, restrict shadow copy permissions).</p>
  53. <p>Module 24 proves whether your process scales. Keep the timeline tight, note decision points, and show defenders exactly how to close the gaps you exploited.</p>

  69. <h5>MAILSRV1</h5>
  70. <p>Before starting a pentest we want to setup and structure our environment as we will collect a huge amount of information in due course.</p>
  71. <p><em>Structuring and isolating data and settings for multiple penetration tests can be quite the challenge. By reusing a Kali VM we could accidentally expose previous-client data to new networks. Therefore, it is recommended to use a fresh Kali image for every assessment.</em></p>
  72. <p>We will create our main directory <code>/home/$USER/OffSec/beyond</code> and two sub-directories for each target we currently have access to. We will also create a <code>creds.txt</code> file to keep track of valid creds and users.</p>
