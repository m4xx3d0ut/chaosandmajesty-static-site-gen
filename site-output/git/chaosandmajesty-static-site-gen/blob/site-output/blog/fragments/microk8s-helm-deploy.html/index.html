    <h2>TLDR;</h2>
<ul>
<li>Enable the <code>helm3</code>, <code>metallb</code>, <code>ingress</code>, and <code>dns</code> addons, and point your chart’s image repository at a local registry address.</li>
<li>Parameterize <code>values.yaml</code> for service type, ingress hosts, and image metadata so you can redeploy with simple overrides.</li>
<li>Package the chart, install it with <code>microk8s helm3 install</code>, then validate pods, services, ingress, and MetalLB IP assignment before curling the app.</li>
</ul>
<h2>Working Notes... In Graphic Detail...</h2>
<h2><strong>Deploying a Custom Helm Chart in MicroK8s with MetalLB and Ingress</strong></h2>
<h3><strong>Custom Helm Chart</strong></h3>
<p>Ensure you have the following setup:</p>
<ul>
<li>MicroK8s installed with <code>helm3</code>, <code>ingress</code>, <code>dns</code>, and <code>metallb</code> enabled.</li>
<li>A local container registry accessible from MicroK8s.</li>
<li>MetalLB configured to allocate an IP range.</li>
<li>A working <code>kubectl</code> context for MicroK8s (<code>microk8s.kubectl</code> or alias to <code>kubectl</code>).</li>
</ul>
<hr>
<h3><strong>Step 1: Create a Helm Chart</strong></h3>
<p>Run the following command to scaffold a new Helm chart:</p>
<pre><code class="language-sh">microk8s helm3 create mychart
cd mychart
</code></pre>
<p>This creates a <code>mychart/</code> directory with the default Helm chart structure.</p>
<hr>
<h3><strong>Step 2: Customize <code>values.yaml</code></strong></h3>
<p>Edit <code>values.yaml</code> to define the service, container image, and Ingress settings.</p>
<h4><strong>Modify the Image Settings</strong></h4>
<p>Ensure the container image references your local registry:</p>
<pre><code class="language-yaml">image:
  repository: my-registry.local:32000/myapp
  tag: latest
  pullPolicy: IfNotPresent
</code></pre>
<p>Replace <code>my-registry.local:32000</code> with your registry&#39;s address.</p>
<h4><strong>Define a Service</strong></h4>
<p>By default, the chart defines a ClusterIP service. Change it to a <code>LoadBalancer</code> type if using MetalLB:</p>
<pre><code class="language-yaml">service:
  type: LoadBalancer
  port: 80
  targetPort: 8080
</code></pre>
<p>Ensure your app listens on port <code>8080</code>.</p>
<h4><strong>Enable Ingress</strong></h4>
<p>Modify <code>values.yaml</code> to define an Ingress resource:</p>
<pre><code class="language-yaml">ingress:
  enabled: true
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
  hosts:
    - host: myapp.local
      paths:
        - path: /
          pathType: ImplementationSpecific
</code></pre>
<p>Ensure your <code>/etc/hosts</code> maps <code>myapp.local</code> to the MetalLB-assigned IP.</p>
<hr>
<h3><strong>Step 3: Update <code>templates/ingress.yaml</code></strong></h3>
<p>Modify <code>templates/ingress.yaml</code> to match <code>values.yaml</code>:</p>
<pre><code class="language-yaml">{{- if .Values.ingress.enabled }}
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: {{ .Release.Name }}
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
spec:
  rules:
  - host: {{ .Values.ingress.hosts[0].host }}
    http:
      paths:
      - path: {{ .Values.ingress.hosts[0].paths[0].path }}
        pathType: {{ .Values.ingress.hosts[0].paths[0].pathType }}
        backend:
          service:
            name: {{ .Release.Name }}
            port:
              number: {{ .Values.service.port }}
{{- end }}
</code></pre>
<hr>
<h3><strong>Step 4: Package and Install the Chart</strong></h3>
<p>Run:</p>
<pre><code class="language-sh">microk8s helm3 package .
</code></pre>
<p>This creates <code>mychart-0.1.0.tgz</code>.</p>
<p>Install it using:</p>
<pre><code class="language-sh">microk8s helm3 install myapp ./mychart-0.1.0.tgz
</code></pre>
<hr>
<h3><strong>Step 5: Verify the Deployment</strong></h3>
<h4><strong>Check Pods and Services</strong></h4>
<pre><code class="language-sh">microk8s kubectl get pods
microk8s kubectl get svc
</code></pre>
<p>Ensure the service has an external IP from MetalLB.</p>
<h4><strong>Check Ingress</strong></h4>
<pre><code class="language-sh">microk8s kubectl get ingress
</code></pre>
<p>Verify the host matches <code>myapp.local</code>.</p>
<hr>
<h3><strong>Step 6: Test Access</strong></h3>
<p>Add an entry to <code>/etc/hosts</code>:</p>
<pre><code class="language-sh">&lt;metallb-ip&gt; myapp.local
</code></pre>
<p>Then, test access:</p>
<pre><code class="language-sh">curl http://myapp.local
</code></pre>
<p>If your app serves HTTP, you should get a response.</p>
<hr>
<h3><strong>Troubleshooting</strong></h3>
<ul>
<li><p>Check logs:</p>
<pre><code class="language-sh">microk8s kubectl logs -l app=myapp
</code></pre>
</li>
<li><p>Describe resources:</p>
<pre><code class="language-sh">microk8s kubectl describe pod &lt;pod-name&gt;
microk8s kubectl describe ingress myapp
</code></pre>
</li>
<li><p>Ensure MetalLB assigned an IP:</p>
<pre><code class="language-sh">microk8s kubectl get svc
</code></pre>
</li>
</ul>
<hr>
<h3>MetalLB Troubleshooting</h3>
<h4><strong>1. Check if MetalLB is Running</strong></h4>
<p>Run:</p>
<pre><code class="language-sh">microk8s kubectl get pods -n metallb-system
</code></pre>
<p>Expected output should show MetalLB components like <code>controller</code> and <code>speaker</code> running:</p>
<pre><code>NAME                          READY   STATUS    RESTARTS   AGE
metallb-controller-xxxxx      1/1     Running   0          3d
metallb-speaker-xxxxx         1/1     Running   0          3d
</code></pre>
<p>If MetalLB is not running, try:</p>
<pre><code class="language-sh">microk8s enable metallb
</code></pre>
<p>It will prompt you to enter an IP range.</p>
<hr>
<h4><strong>2. Check for MetalLB Resources</strong></h4>
<p>MicroK8s may be using a <code>Custom Resource Definition (CRD)</code> instead of the old <code>ConfigMap</code>. Check for <code>IPAddressPools</code>:</p>
<pre><code class="language-sh">microk8s kubectl get ipaddresspools.metallb.io -A
</code></pre>
<p>If an IP address pool exists, describe it:</p>
<pre><code class="language-sh">microk8s kubectl describe ipaddresspools.metallb.io default-addresspool -n metallb-system
</code></pre>
<hr>
<h4><strong>3. Reconfigure MetalLB (If CRD is Used)</strong></h4>
<p>If the <code>ConfigMap</code> is missing but <code>IPAddressPools</code> exists, update the IP range by editing the <code>IPAddressPool</code> resource:</p>
<pre><code class="language-sh">microk8s kubectl edit ipaddresspools.metallb.io &lt;pool-name&gt; -n metallb-system
</code></pre>
<p>Modify the <code>addresses</code> section:</p>
<pre><code class="language-yaml">spec:
  addresses:
    - 192.168.1.100-192.168.1.200
</code></pre>
<p>Save and exit.</p>
<hr>
<h4><strong>4. Manually Create an IP Pool (If None Exists)</strong></h4>
<p>If there is no existing <code>IPAddressPool</code>, create one:</p>
<pre><code class="language-yaml">cat &lt;&lt;EOF | microk8s kubectl apply -f -
apiVersion: metallb.io/v1beta1
kind: IPAddressPool
metadata:
  name: my-ip-pool
  namespace: metallb-system
spec:
  addresses:
    - 192.168.1.100-192.168.1.200
---
apiVersion: metallb.io/v1beta1
kind: L2Advertisement
metadata:
  name: my-l2-advert
  namespace: metallb-system
EOF
</code></pre>
<p>This defines an IP pool and advertises it to the cluster.</p>
<hr>
<h4><strong>5. Verify New Configuration</strong></h4>
<p>After making changes, check:</p>
<pre><code class="language-sh">microk8s kubectl get ipaddresspools.metallb.io -n metallb-system
microk8s kubectl get svc -A | grep LoadBalancer
</code></pre>
<hr>
<h3>MetalLB Static IP Assignment</h3>
<h4><strong>1. Define a <code>IPAddressPool</code> for a Static IP Range</strong></h4>
<p>Ensure your MetalLB IP pool includes the static IPs you want to assign. If you haven&#39;t already, create or edit an <code>IPAddressPool</code> to include <code>192.168.29.16</code> and <code>192.168.29.17</code>:</p>
<pre><code class="language-sh">microk8s kubectl edit ipaddresspools.metallb.io my-ip-pool -n metallb-system
</code></pre>
<p>Modify or add:</p>
<pre><code class="language-yaml">spec:
  addresses:
    - 192.168.29.16-192.168.29.17
</code></pre>
<p>If an <code>IPAddressPool</code> doesn’t exist, create one:</p>
<pre><code class="language-sh">cat &lt;&lt;EOF | microk8s kubectl apply -f -
apiVersion: metallb.io/v1beta1
kind: IPAddressPool
metadata:
  name: my-ip-pool
  namespace: metallb-system
spec:
  addresses:
    - 192.168.29.16-192.168.29.17
---
apiVersion: metallb.io/v1beta1
kind: L2Advertisement
metadata:
  name: my-l2-advert
  namespace: metallb-system
EOF
</code></pre>
<hr>
<h4><strong>2. Assign a Static IP in Your Helm Chart</strong></h4>
<p>Modify your Helm chart&#39;s <code>values.yaml</code> to request a specific IP from MetalLB:</p>
<pre><code class="language-yaml">service:
  type: LoadBalancer
  loadBalancerIP: 192.168.29.16
  port: 80
  targetPort: 8000
</code></pre>
<p>For the next service, assign <code>192.168.29.17</code>:</p>
<pre><code class="language-yaml">service:
  type: LoadBalancer
  loadBalancerIP: 192.168.29.17
  port: 80
  targetPort: 8080
</code></pre>
<hr>
<h4><strong>3. Deploy the Helm Chart</strong></h4>
<p>After modifying <code>values.yaml</code>, deploy (or upgrade) the chart:</p>
<pre><code class="language-sh">microk8s helm3 upgrade --install youtube-integ ./youtube-integ-chart
</code></pre>
<p>Then, verify the assigned IP:</p>
<pre><code class="language-sh">microk8s kubectl get svc -A | grep LoadBalancer
</code></pre>
<p>It should show <code>192.168.29.16</code> assigned persistently.</p>
<hr>
<h4><strong>4. Configure Local DNS</strong></h4>
<p>Now, map the static IP to <code>youtube-integ.local</code> in your local DNS or <code>/etc/hosts</code>:</p>
<pre><code class="language-sh">echo &quot;192.168.29.16 youtube-integ.local&quot; | sudo tee -a /etc/hosts
</code></pre>
<p>Test with:</p>
<pre><code class="language-sh">curl http://youtube-integ.local
</code></pre>
<hr>
<h4><strong>5. Repeat for Other Services</strong></h4>
<p>For the next service, ensure <code>values.yaml</code> specifies:</p>
<pre><code class="language-yaml">service:
  type: LoadBalancer
  loadBalancerIP: 192.168.29.17
</code></pre>
<p>Then, deploy it and map <code>192.168.29.17</code> in DNS.</p>
<p>Now, your services will always get the correct IPs even after uninstalling/reinstalling! 🚀</p>
