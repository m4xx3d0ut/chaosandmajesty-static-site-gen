    <h2>Abstract (Executive)</h2>
<p>This paper outlines how a local development environment can be configured for Nvidia vGPU utilizing the KVM hypervisor.  Sections marked &quot;Executive&quot; are for high level consumption and all others should be assumed technical. </p>
<p>Our primary focus will be <a href="https://ubuntu.com/openstack">Canonical OpenStack</a> single-node deployments, on <a href="https://releases.ubuntu.com/jammy/">Ubuntu Server 22.04.3 LTS</a>, with <a href="https://docs.openstack.org/nova/latest/">Nova Compute</a> configured for the <a href="https://linux-kvm.org/page/Main_Page">KVM hypervisor</a>, however a similar end can be achieved with a basic Ubuntu Linux server deployment and the <a href="https://ubuntu.com/blog/kvm-hyphervisor">KVM hypervisor</a>.  We will enable and utilize the Nvidia datacenter vGPU feature, present in the majority of Nvidia cards but only enabled on the datacenter class devices, and show the value (in both cost and capability) the system achieves. The yield is an advanced local development environment for distributed cloud system, designed to run GPU workloads, and capable of complex network architectures.</p>
<p><em>Paul Kolesa (The Architect), Infinite Reality R&amp;D</em></p>
<hr>
<h2>Host System Configuration</h2>
<h3>Nvidia Grid Drivers</h3>
<p>Nvidia vGPU requires the host system be configured with a datacenter class Nvidia GPU and the Nvidia Grid graphics driver, which is only available through the <a href="https://nvid.nvidia.com/">Nvidia Application Hub</a>.</p>
<p>If a datacenter class Nvidia GPU is not available it is possible to patch the Grid host driver, <a href="https://gitlab.com/polloloco/vgpu-proxmox">using patches from the Proxmox project</a>, to recognize a Geforce class graphics card as a datacenter class card of like architecture. For example, the Geforce RTX Titan with patched Grid driver is identified as the datacenter class RTX6000.  In fact, the only architectural difference between the two cards is a 90 Mhz overclock and $1,500 price difference (Yes, Nvidia is robbing you!).</p>

<p>A simple bash script can be used to define and start a mdev node.</p>
<pre><code># cat def-mdev.sh
U=$(uuidgen)
P=$1
T=$2

echo &quot;[+] Create mdev: $U&quot;
echo &quot;[*] mdevctl start -u $U -p $1 -t $2&quot;
bash -c &quot; mdevctl start -u $U -p $1 -t $2&quot;
</code></pre>
<p>The example command will create a single node of the given type on the given parent.</p>
<pre><code># ./def-mdev.sh 0000:01:00.0 nvidia-261
</code></pre>
<ul>
<li>Note that <code>nvidia-261</code> type can create a max of 3 mdev nodes, as noted in type output above.</li>
</ul>

<h2>Nvidia Licensing Server</h2>
<p>The simplest solution here is to configure a hosted license server through the <a href="https://nvid.nvidia.com/">Nvidia Application Hub</a>, documentation on the process can be found <a href="https://docs.nvidia.com/grid/13.0/grid-licensing-user-guide/index.html">here</a>. You will need to download the license tokens generated by the server and will later transfer them to the guest systems, 1 token per guest will be required so provision your licenses accordingly.</p>
<hr>
<h2>Guest System Configuration</h2>
<h3>Provisioning the VM</h3>
<p>The first step, of course, is to provision your VM. A KVM hypervisor is shown here, but docs can be found for other popular hypervisors. We will show examples from OpenStack, but the process is similar with the <code>virsh</code> CLI and <code>virt-manager</code> GUI.</p>
<p>First configure a flavor with the VGPU requirement using the OpenStack CLI.</p>
<pre><code>$ openstack flavor create --id 7 --ram 8128 --swap 8128 --disk 160 --vcpus 8 m1.xlr8gpu
$ openstack flavor set m1.xlr8gpu --property &quot;resources=VGPU=1&quot;
</code></pre>
<ul>
<li>Note that:<ul>
<li>the parameters above are arbitrary and should be set corresponding to your environment</li>
</ul>
</li>
</ul>
<p>Create a VM with the flavor.</p>
<pre><code>openstack --os-cloud=kolla-admin server create \
    --image jammy-server-cloudimg-amd64 \
    --flavor m1.xlr8gpu \
    --key-name &#39;test-key-0&#39; \
    --network &#39;test-network-0&#39; \
    --wait &#39;test-gpu-0&#39;
</code></pre>
<p>Depending on your deployment and a number of other factors, it is possible the mdev node has not attached to the instance during creation. To quickly check this you can SSH into the new VM and check the attached PCI devices.</p>
<pre><code class="language-bash">(venv) ubuntu@test-gpu-1:~/CodeLlama-7b-Python-hf$ lspci
00:00.0 Host bridge: Intel Corporation 440FX - 82441FX PMC [Natoma] (rev 02)

00:01.2 USB controller: Intel Corporation 82371SB PIIX3 USB [Natoma/Triton II] (rev 01)
00:01.3 Bridge: Intel Corporation 82371AB/EB/MB PIIX4 ACPI (rev 03)
00:02.0 VGA compatible controller: Red Hat, Inc. Virtio GPU (rev 01)
00:03.0 Ethernet controller: Red Hat, Inc. Virtio network device

00:07.0 Unclassified device [00ff]: Red Hat, Inc. Virtio memory balloon
00:08.0 Unclassified device [00ff]: Red Hat, Inc. Virtio RNG
</code></pre>
<ul>
<li>Note the presence of <code>NVIDIA Corporation TU102GL [Quadro RTX 6000/8000] (rev a1)</code><ul>
<li>indicating the vGPU is attached to the instance</li>
</ul>
</li>
</ul>
<p>If a vGPU has not attached to the instance, first stop the instance from Horizon, then access a <code>virsh</code> shell on the Kolla Ansible OpenStack <code>nova_libvirt</code> Docker container, and edit the XML of the VM to manually attach the node.</p>
<p>List the available VMs.</p>
<pre><code>docker exec -it -u 0 nova_libvirt virsh list --all
</code></pre>
<p>Edit the corresponding VM XML.</p>
<pre><code>docker exec -it -u 0 nova_libvirt virsh edit instance-00000001
</code></pre>
<p>Edit the UUID for your environment and add this block into the <code>&lt;device&gt;</code> section near the end of the XML.</p>
<pre><code>    &lt;hostdev mode=&#39;subsystem&#39; type=&#39;mdev&#39; managed=&#39;no&#39; model=&#39;vfio-pci&#39; display=&#39;on&#39;&gt;
      &lt;source&gt;
        &lt;address uuid=&#39;fa6d5d93-cc58-4ad8-839e-113bb6f8ba6f&#39;/&gt;
      &lt;/source&gt;
    &lt;/hostdev&gt;
</code></pre>
<ul>
<li>Note that the UUID should correspond the the UUID of the mdev node recorded earlier</li>
</ul>
<p>Save the XML, exit, and start the VM from Horizon. Recheck the PCI devices attached to the instance, the Nvidia vGPU should now present itself.</p>
<h3>Install and Configure the Guest Nvidia Grid Driver</h3>
<p>The Grid driver archive you downloaded earlier should also contain a &quot;Guest&quot; driver sub-folder, transfer it to the VM along with the token downloaded from the license server.</p>
<p>If necessary, unpack your guest driver package, mark the run script executable, and install with <code>dkms</code>.</p>
<pre><code>$ chmod +x NVIDIA-Linux-x86_64-535.104.05-grid.run
$ sudo ./NVIDIA-Linux-x86_64-535.104.05-grid.run --dkms
</code></pre>
<p>Next set the permissions of the license token to <code>744</code>, copy it to the <code>ClientConfigToken</code> directory, edit the <code>gridd.conf.template</code>, save it as <code>gridd.conf</code>, and restart <code>nvidia-gridd.service</code>.</p>
<pre><code>$ chmod 744 client_configuration_token_*.tok
$ sudo cp client_configuration_token_*.tok /etc/nvidia/ClientConfigToken/
$ sudo vi /etc/nvidia/gridd.conf.template
$ sudo systemctl restart nvidia-gridd.service
</code></pre>
<ul>
<li>Note that the only require option to set in the <code>gridd.conf</code> is <code>FeatureType=1</code></li>
</ul>
<p>Verify the vGPU with <code>nvidia-smi</code>.</p>
<pre><code>$ nvidia-smi

<h2>Research Results &amp; Conclusions (Executive)</h2>
<p>GPU virtualization is a simple and effective way to create a development environment for multi-node, GPU compute, systems. There is a considerable cost savings over time when compared to 3rd party cloud development environments. The breakdown below assumes a requisition of a Nvidia A10 datacenter class graphics card, retail cost is approximately $3k. We exceed the purchase cost of the A10 with a comparable AWS Instance, in use for 8 hours a day, in just 2 months. At 24 hours a day utilization that drops to just 21 days!</p>
<p>Although a high end custom system is required to run a single-node OpenStack deployment, most modern gaming systems with high end Nvidia graphics cards fully capable of running Ubuntu Server 22.04.3 with <a href="https://ubuntu.com/blog/kvm-hyphervisor">KVM hypervisor</a> and a small number of vGPU VMs configured through <code>virsh</code>/<code>virt-manager</code> achieving the same ends. In most cases a RAM upgrade and Nvidia vGPU license will be the only other requirement.</p>
<p>There are also numerous added benefits to be gained from the hypervisor deployment including snapshots, image backup, reconfigure with simple XML edits, and the ability to design complex architectures for local development. Rolling back a failed system to a known good state becomes trivial and any number of GPU deployments can be configured, most cards support time-slice vGPU and Ampere or newer support <a href="https://docs.nvidia.com/datacenter/tesla/mig-user-guide/index.html">Multi-Instance GPU (MIG)</a>. MIG capable cards provide a fully dedicated logical vGPU, at the expense of 1/7th the cards resources.</p>
<p>Extending these development environments with network bridge interfaces and/or <a href="https://www.openvswitch.org/">Open vSwitch</a> layers allow for complex network architecture to be constructed locally, fully replicating the network architecture of the deployment target.</p>
